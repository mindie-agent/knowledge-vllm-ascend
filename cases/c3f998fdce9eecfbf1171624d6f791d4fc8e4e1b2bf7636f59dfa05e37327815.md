title: Bounded Ascend torch_npu RMSNorm validation with dtype-rounded FP16/BF16 references and logical-device normalization
---

Problem and background: verify numerical correctness of torch_npu.npu_rms_norm on a real Ascend NPU for shape [7, 2048], using seed 20260921 and epsilon 1e-6. The check was explicitly scoped to one mapped logical device and did not attempt model serving or performance validation.

Device setup correction: the initial environment exposed ASCEND_RT_VISIBLE_DEVICES=8 while the container exposed one logical device. Before importing torch and torch_npu, the script applied:

```python
initial_visible_env = os.getenv("ASCEND_RT_VISIBLE_DEVICES")
if initial_visible_env == "8":
    os.environ["ASCEND_RT_VISIBLE_DEVICES"] = "0"
```

It then required `torch.npu.device_count() > 0`, called `torch.npu.set_device(0)`, and recorded the device name and current logical device. This corrected visibility for the bounded test; it did not prove that physical NPU 8 maps to logical device 0. The result recorded `device_count=1`, `device_name="Ascend910_9362"`, `logical_device=0`, and `physical_mapping_verified=false`.

Reference and correction method: generate FP32 random tensors, round each input to the tested dtype on CPU, and compute the reference in FP32 from those rounded values. The essential comparison was:

```python
x_cpu = x32.to(dtype)
w_cpu = w32.to(dtype)
x = x_cpu.npu()
w = w_cpu.npu()
y, _ = torch_npu.npu_rms_norm(x, w, epsilon=epsilon)
torch.npu.synchronize()
xf = x_cpu.float()
wf = w_cpu.float()
reference = xf * torch.rsqrt((xf * xf).mean(-1, keepdim=True) + epsilon) * wf
```

This avoids mixing FP32-to-low-precision input conversion error into the operator comparison. Each case required finite outputs and used `atol=rtol=4 * torch.finfo(dtype).eps`.

Observed results from the recorded result JSON: FP16 produced `max_abs_error=0.003387451171875`, `max_relative_error=0.0004873290890827775`, tolerance `0.00390625`, and `allclose=true`. BF16 produced `max_abs_error=0.01551961898803711`, `max_relative_error=0.003857600037008524`, tolerance `0.03125`, and `allclose=true`. Both cases were finite and the overall result was `passed=true`; the NPU output dtypes matched the tested input dtypes.

No execution failure was recorded. The unresolved limitation is topology: the requested physical device was 8, but physical-to-logical mapping was not independently verified. Do not generalize this result to other Ascend models, shapes, epsilon values, containers, hosts, device mappings, multiple NPUs, serving correctness, throughput, memory, or performance without additional tests.
