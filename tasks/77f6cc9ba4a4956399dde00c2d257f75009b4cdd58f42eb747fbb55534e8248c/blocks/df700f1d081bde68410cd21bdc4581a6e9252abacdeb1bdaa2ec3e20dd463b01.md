KDA/conv 的正确计数定义是：

```text
x = 接收的 draft 数，范围 0…7
L = commit_len = x + 1，包含 target bonus，范围 1…8
正确状态 = verify scratch/state 的第 L-1 步
```

所以最危险的 off-by-one 是把 `L` 当成 drafts-only：

- 用 `L` 取状态：多前进一步；
- 先把 `L` 减成 drafts 数再减一次：少前进一步；
- 当前 `count(sampled_token_ids != -1) - 1` 在“有效输出包含 bonus”的前提下是正确的。

尤其重要：24.23% 的精确启动脚本是 prefix-cache `off`，因此 `postprocess_mamba_align` 不在该基线关键路径上。align-copy 即使有问题，也解释不了这次 24.23%。优先级应放在：

1. 首轮 hidden capture 数值是否与 SGLang 相同；
2. draft embedding/lm_head 是否真实共享 target 参数；
3. anchor/query 构造与 target logits 对齐；
4. 只有“第 1 轮正常、第 2 轮开始崩”时，再集中查 KDA/conv 状态提交。

