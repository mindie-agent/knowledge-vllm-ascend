3. async on/off 的实际差异

worker RPC 仍严格保持：

```text
execute_i → sample_i → execute_{i+1}
```

async 模式真正增加的是跨 batch 的未完成设备尾部：

- async 时 `max_concurrent_batches=2`，sync 为 1，见 core [vllm.py](<redacted:local-path:a5a58810c106>:512)。
- batch queue 可在上一 batch output 尚未 settle 时继续排下一 batch，见 [core.py](<redacted:local-path:7b9068d65284>:617)。
- async sample 使用 copy stream 和后台 `get_output()`；主 worker 不等待它，见 [gpu_model_runner.py](<redacted:local-path:8bb68053e024>:258) 与 [multiproc_executor.py](<redacted:local-path:57ca9ffe5080>:939)。
- sync 路径通过 transfer event synchronize 形成 drain，见 [gpu_model_runner.py](<redacted:local-path:8bb68053e024>:7757)。
- async 开关还会改变 DP synchronization 配置，见 [vllm.py](<redacted:local-path:a5a58810c106>:1114)。

因此 async-off 通过只能证明“异步 batch timing 是必要条件”，不能单独证明 async output copy 是根因。

5. 建议的生产修复

不要把永久关闭 multistream 当最终修复。最小且保留 overlap 的方案是：

```text
shared_forward_impl:
  在默认流上对 shared_hidden_states 做 TP all-gather
  记录 before_routed_experts event
  默认流进入 routed EP64/MC2
  side stream 等待该 event
  side stream 只执行 shared quant/matmul/activation
  默认流 wait shared stream
  默认流执行 shared TP reduce-scatter
```

实现 seam 在 [fused_moe.py](<redacted:local-path:781a1be6fc90>:897)：

- 仅在 `multistream_overlap_shared_expert && _flashcomm_uses_tp_shared_experts` 时 pre-gather；
- 把 gathered tensor 传给 `_forward_shared_experts`，并显式标记 `input_already_prepared`，避免二次 AG；
- `before_routed_experts` 必须在 pre-gather 之后记录，使 side stream 的数据依赖完整。

这样每层均形成默认流上确定的 `TP AG → EP64 MC2` 顺序，同时 shared MLP 仍可与 routed compute 重叠。保守证伪版可让 side AG 等 routed-done event，但会基本消灭 overlap，不宜作为最终方案。
