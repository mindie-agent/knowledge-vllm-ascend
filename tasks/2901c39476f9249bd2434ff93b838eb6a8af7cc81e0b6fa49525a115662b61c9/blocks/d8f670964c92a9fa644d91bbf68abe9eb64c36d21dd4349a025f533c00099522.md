### user
为什么mtp的场景当mtp=7的时候一条请求的seqlens会等于8


### assistant:commentary
我先沿着当前代码里的 MTP/speculative decode 路径核对一下 `seqlens` 的定义；关键通常是它统计“当前 token + 7 个草稿 token”，而不是只统计 MTP 草稿数。

### assistant:commentary
已经对上了：这里的 `8` 是 target 校验阶段的宽度 `1 + 7`，不是说 MTP 额外草拟了 8 个 token，也不是说 8 个都已经被接受。

### assistant:final_answer
因为 `mtp=7` 表示“草拟 7 个 token”，而 target model 校验时还要带上本轮的起始/anchor token，所以：

```text
target 输入 = [anchor, draft1, draft2, ..., draft7]
query_len   = 1 + 7 = 8
```

这 8 个位置的作用是：

```text
anchor → 校验 draft1
draft1 → 校验 draft2
...
draft6 → 校验 draft7
draft7 → 产生 bonus token
```

因此代码明确使用：

```python
decode_query_len = 1 + num_speculative_tokens
```

见 [platform.py](<redacted:local-path:38b9ba2aeac0>:1304) 和 [model_runner_v1.py](<redacted:local-path:86d6937a1949>:3175)。

需要区分：

- `query_len` 或 `cu_seqlens` 相邻差值：一条请求是固定 `8`。
- runner 的总 `seq_lens`：通常是 `已缓存长度 + 8`，代码是 `num_computed_tokens + num_scheduled_tokens`，见 [model_runner_v1.py](<redacted:local-path:86d6937a1949>:1205)。
- `8` 是本轮乐观调度/校验宽度，不代表 8 个 token 已经全部接受；最终推进多少仍取决于验收结果。
