### user

### assistant:final_answer
对。A3 路由专家的真实需求是：

`BF16 GMM1 输出 → SiTU → per-token dynamic quant → INT8 + FP32 scale`

因此本质上需要的是 `SiTUQuant`，而不是反量化算子：

- GMM1 已经利用 weight scale、activation scale 和 bias 完成反量化，输出 BF16。
- SiTU 阶段不再需要 `weight_scale`、`activation_scale`、`bias` 或 `group_index`。
- GMM2 的 W4A8 输入需要 INT8 activation 和 per-token scale，所以只做 `SiTU` 还不够，之后仍要接 dynamic quant。
- `SiTU + npu_dynamic_quant` 两个算子功能上也可以，但会增加一次中间 Tensor 写回和 kernel launch。

所以当前最合适的是复用 `DequantSituQuant` 的 BF16 分支，把所有反量化参数传空；它实际执行的就是 `SiTUQuant`。等上游提供正式 `SiTUQuant` 接口后再直接替换即可。
