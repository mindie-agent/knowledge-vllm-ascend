### e32 的代码边界

[e32 patch](<redacted:local-path:b7352cdf4627>:38) 只做了两件事：

1. 在 `synchronize_input_prep` event scope 内，对 `src_ptrs/dst_ptrs/sizes` 三个复用 pinned buffer 执行 H2D。
2. KV connector load 后，Triton memcpy 仅消费已经 staged 的 GPU ptr-table。

实际 state copy 仍位于 [model_runner_v1.py](<redacted:local-path:f4671869f339>:2091) 的 KV connector context 内、model forward 前。

它没有覆盖：

- source/destination state tensor 自身的生产、复用和回收生命周期
- block-table/state-index/source-column 的持久 GPU 元数据
- actual state-copy kernel 的独立 completion event
- V1 fused GPU pre-copy 的 persistent base/stride/element-size/conv-layout metadata
- `src_col/dst_col/token_bias` 在 GPU 上解析并执行 DS-conv/recurrent copy 的系统路径

这与 `f51193b9a` 不等价。后者引入 persistent `MambaSpecDecodeGPUContext`，每轮只上传 `state_idx/src_col/token_bias`，由 GPU 根据持久 layout/block-table metadata 做 fused precopy。Ascend 移植仍需保持当前约束：元数据可在 prep scope staging，但 fused state copy 必须适配 KV-load-after-copy 顺序，不能直接照搬成 KV load 前执行。
