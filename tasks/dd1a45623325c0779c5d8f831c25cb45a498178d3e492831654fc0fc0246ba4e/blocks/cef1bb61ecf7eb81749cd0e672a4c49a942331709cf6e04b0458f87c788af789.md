## 第 2 页：Agent 怎么把多卡日志变成“一条可比较的时间线”

标题建议：

**海量日志不是逐行读完，而是先被 Agent 编译成一条时间线**

副标题：

**先粗定位是哪一阶段，再精确比较同一请求、同一步、同一块状态。**

### 主流程图节点

建议从左到右画 8 个节点：

```text
① 冻结实验身份
      ↓
② Agent 生成采集脚本
      ↓
③ 64 rank 粗粒度扫描
      ↓
④ 目标 DP 的 16 TP 结构化采集
      ↓
⑤ 清洗与统一字段
      ↓
⑥ 按业务身份对齐
      ↓
⑦ 计算轻量指纹并比较
      ↓
⑧ 输出“最早差异卡”
```

每个节点里的正文如下。

### ① 冻结实验身份

```text
commit
模型与权重
prompt token hash
request ID
DP / TP rank
实验开关
```

效果：

> 先证明比较的是同一份代码、同一个请求，避免把版本漂移当成精度差异。

---

### ② Agent 生成采集脚本

Agent 为所有 rank 生成统一记录格式：

```text
{
  request,
  dp,
  tp,
  step,
  stage,
  layer,
  group,
  block,
  shape,
  finite_count,
  hash
}
```

效果：

> 不让 64 个进程各说各话；后续脚本可以直接 join、排序和比较。

---

### ③ 64 rank 粗粒度扫描

只扫描：

```text
最后完成的阶段
当前 collective 序号
错误 / 超时
请求是否返回
```

效果：

> 先判断是一个 rank 掉队，还是所有 rank 在同一个位置等待。

真实结果：

```text
所有 TP rank 停在同一阶段
→ 排除单 rank 掉线
→ 向更早的异步计算继续追
```

---

### ④ 目标 DP 的 16 TP 结构化采集

全量健康扫描覆盖 64 workers；精度定位则只聚焦问题所在 DP 的 16 个 TP rank：

```text
scheduler.jsonl
worker-tp00.jsonl
...
worker-tp15.jsonl
```

效果：

> 既保留全局视角，又避免一上来 dump 64 份大 Tensor。

---

### ⑤ 清洗与统一字段

Agent 自动完成：

```text
去重
request-aware chunk 合并
统一 stage 名
统一单调时钟
补齐 rank 和 block 身份
生成 manifest 与文件 hash
```

这里可以讲一个很真实的细节：

> 最早一版采集器把三个 prefill chunk 当成三个请求。Agent 在分析时发现 request ID 相同，主动修正为“按请求去重”，避免用错误样本做根因判断。

这个细节很好，因为它说明 Agent 不只是处理日志，也会检查日志本身是否可信。

---

### ⑥ 按业务身份对齐

不要按日志行号，也不要只按墙上时间，而是按：

```text
request ID
+ step
+ stage
+ layer/group
+ logical block
```

再额外建立：

```text
logical block → physical page/address
```

效果：

> 即使各 rank 打印速度不同，也能比较“同一个请求的同一个状态”。

---

### ⑦ 计算轻量指纹并比较

第一轮不保存完整 Tensor，只保存：

```text
shape
finite / nonfinite 数量
min / max
内容 hash
block 与物理地址
首 token
Prefix hit
```

比较顺序：

```text
rank vs rank
warm vs hit
stage N vs stage N+1
writer vs reader
```

效果：

> 大段日志被压缩成“每个阶段一行指纹”；只有发现差异的层和块才升级为定向 Tensor dump。

---

### ⑧ 输出“最早差异卡”

最后不是给人一堆日志，而是自动生成类似：

```text
最早差异
Request: hit896
范围: TP00–TP15 全部一致
Before: block 143，finite
After: 下一次 real execute，98,304 个状态值 nonfinite
中间事件: 0-token idle wave
下一轮实验: 禁止 dummy 更新 recurrent state
```

另一个地址归属结果可以作为第二张小卡：

```text
最早异常读取
Target layer 23：448 NaN
对应物理 backing 的先前写入者：
Draft layer 94 / block 1969
```

### 这一页最明确的效果

页面右下角可以放三句：

```text
64 份日志 → 1 张全 rank 阶段矩阵
17 份结构化记录 → 1 条请求生命周期
“输出坏了” → “第一次变坏发生在这里”
```

### 动画建议

1. 先出现 4 组、每组 16 个 worker 点，共 64 个。
2. 所有点产生不同长度的灰色日志流。
3. 日志流进入 Agent 的“结构化处理器”，收缩成四列 DP。
4. 聚焦 DP0，16 条 TP 时间线自动横向对齐。
5. 正常阶段全部为绿色。
6. 第一个共同变红的格子亮起，其余日志淡出。
7. 右侧弹出“最早差异卡”和“下一轮实验”。

最后可以用一句比较自然的话收住：

> 人要做的不是翻完 64 份日志，而是判断 Agent 给出的“最早差异”是否真的能解释现象；如果不能，就让下一轮实验继续推翻它。
