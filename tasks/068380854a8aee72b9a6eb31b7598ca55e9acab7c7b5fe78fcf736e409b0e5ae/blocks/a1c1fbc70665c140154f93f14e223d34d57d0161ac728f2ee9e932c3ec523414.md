### Blocker

[P1] [`_bind_packed_conv_weights()`](<redacted:local-path:452bbf70aa50>:322) 直接写 `self._buffers[name] = packed`，不能恢复 buffer 的 `persistent=False`。

目标 vLLM v0.25.1 在 layerwise restore/finalize 时用默认 `persistent=True` 重新注册 buffer。因此 reload 后该 derived buffer 会进入 `state_dict()`，污染 checkpoint/sharded save-load。

最小常规修复是始终重新注册：

```python
self.register_buffer(buffer_name, packed, persistent=False)
```

同时补测试：真实走完 `initialize_layerwise_reload -> finalize -> pack` 后，buffer 仍在 `named_buffers()`，但不在 `state_dict()`。配套 core 分支虽已有通用修复，但当前 Ascend PR 不应隐式依赖尚未保证合入的 core 行为。

### `load_weights()` 覆盖结论

仅在 `KimiK3TextModel.load_weights()` 末尾 pack 不够：

| 场景 | 是否可靠 |
|---|---|
| 普通 Default/Tensorizer 等初始加载 | 基本可以 |
| Dummy/Sharded/custom loader 初始加载 | 不可以，可能绕过 model `load_weights()` |
| 整 checkpoint reload | 不可靠；调用顺序是 `initialize(meta) -> model.load_weights -> finalize`，pack 时尚未到完整终态 |
| kernel-format reload | 不可以，直接 `param.copy_()`，绕过 model `load_weights()` |
| 分块 layerwise 更新 | 明确不可以；每个 chunk 结束时其他 KDA 层仍可能是 meta/旧权重 |

因此当前最小方案是正确方向：

- MRV1 初始加载完成后 pack，且必须位于 offloader `post_init()` 和 ACLGraph 包装之前。
- MRV2 在 `super().load_model()` 完成后 pack。
- 整体 reload 在 `super().reload_weights()` 返回、即 finalize 完成后 pack。
- 在线 layerwise 更新仅在 `finish_weight_update()` 的 finalize 之后 pack。
- reload/finish 后同步 NPU。

不建议再把 pack 塞进 `KimiK3TextModel.load_weights()`，会重复执行并破坏分块更新语义。

### 其他边界

- PP 只遍历当前 rank 实际存在的 KDA 层，正确。
- 多模态和 CausalLM wrapper 的转发正确。
- ACLGraph 使用预分配稳定地址、reload 原地 `copy_()`，设计正确。
- Prefetch offload 初次加载顺序正确；但其 `post_init()` 后各层参数指向复用的 static buffer，所以“prefetch offload + 后续 whole/layerwise reload”不能宣称支持，除非以后从独立 CPU canonical storage 重建 packed weight。
- graph capture 后再对模型调用 `.to()` 会更换 buffer 地址；正常生命周期不会这样做，但最好补测试或明确限制。

### 其他 transpose/layout 盘点

当前适合本提交消除的只有 causal-conv q/k/v weight 的静态 transpose/cat/cast，移到加载生命周期是对的。

这些不应混入本提交：

- `mixed_qkv.chunk()` 后 q/k/v 的 `contiguous()` 是真实 deinterleave，算子需要。
- recurrent cache 的 `[H,V,K] <-> [H,K,V]` transpose 是两个算子布局不同造成的动态边界，不能移到 init。
- `mixed_qkv = cat(...)` 若要消除，需要 fused QKV projection/量化加载重构。
- `A_log.reshape().contiguous()`、`dt_bias.contiguous()` 通常不分配，不值得增加 derived-buffer 生命周期。
- 后续独立优化可评估 NTD prefill，可能融合 deinterleave 并减少 binding 内部 BSND→BNSD layout swap；无需改 AscendC kernel，但必须单独做 NPU 精度和性能验证。
- output merge 的临时 `cat/empty/index_copy` 也可独立评估直接写入 `core_attn_out`。

SGLang 同样采用加载期绑定卷积权重，但 recurrent-state transpose 仍保留，与上述边界一致。

### 阻塞项

1. [P1] Direct/kernel-format weight update 不会触发 pack hook。

[`_wrap_conv_process_weights()`](<redacted:local-path:452bbf70aa50>:332) 只在 `quant_method.process_weights_after_loading()` 被调用时更新 derived buffer。但是以下正式路径直接执行 `param.copy_()`：

- [`NPUWorker.update_weights(is_checkpoint_format=False)`](<redacted:local-path:36989549d706>:341)
- vLLM `GPUModelRunner.reload_weights(is_checkpoint_format=False)`

复制完成后 q/k/v 参数已更新，packed buffer 仍是旧值，之后所有 KDA forward 都静默使用旧卷积权重。旧热路径每次从当前参数生成权重，没有这个回归。现有测试在 `param.copy_()` 后手工调用 quant hook，因而没有覆盖真实 direct-update 行为。

算子局部无法可靠感知任意 `param.copy_()`；要修复必须恢复 weight-update/reload 完成钩子，或重构 canonical parameter storage，均超出当前约束。

2. [P1] 目标 vLLM v0.25.1 的 layerwise finalize 会破坏 non-persistent 语义。

仓库明确固定使用 [`.github/vllm-release-tag.commit`](<redacted:local-path:f1f5e22a4136>:1) 的 `v0.25.1`。该版本 finalize 会再次用默认 `persistent=True` 注册 KDA parent buffer。

当前测试在 [`if not vllm_version_is("0.25.1")`](<redacted:local-path:0daaaf32db06>:242) 中主动跳过这一契约。结果是 layerwise reload 后 derived buffer 会进入 `state_dict()`；随后保存的 sharded checkpoint 含额外 derived key，而新模型的 non-persistent state dict 不接受该 key，存在保存后无法正常重载的风险。

main core 的通用修复可以解决，但当前 PR 不能假设它已存在。算子内 hook 执行早于 parent finalize，无法最终恢复该属性。
