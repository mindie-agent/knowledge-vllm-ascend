### 七端的关键结论

| Harness | 已有基础与适配重点 |
|---|---|
| **Codex** | 有独立任务协调、会话配置和运行中输入接口。重点验证 Skill/MCP 的逐会话覆盖及恢复；额外 Skill 根存在进程级作用域。[文档](https://learn.chatgpt.com/docs/app-server) |
| **Claude Code** | 路径最明确：正式支持普通独立会话间 `ListAgents / SendMessage`，配合 Agent View 可分别查看、进入并指导各会话。[通信](https://code.claude.com/docs/en/cross-session-messaging)、[界面](https://code.claude.com/docs/en/agent-view) |
| **Cursor** | Local SDK 有明确的 MCP 配置控制。需要进一步落实同一条路径上的领域 Skill 限制、原生界面接入和会话通信；云端与本地 SDK 能力不能混用。[文档](https://prod.cursor.com/docs/sdk/python) |
| **Kimi Code** | CLI 有指定 Skill 根和工具名单的基础。**Web API 虽接受部分工具/MCP 配置字段，却明确尚未应用**，适配时必须避开这一缺口。[文档](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/server-api.html) |
| **DeepSeek Harness** | 不同 preset 可以承载不同领域的普通 Web 会话。需要补小型会话协作工具，复用现有 Session Controller；普通子 Agent 会继承父配置，不能直接用于领域切换。[Preset](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-presets/README.md) |
| **Z Code** | Plugin、MCP、任务界面都有；禁用 Skill 后确实不注入、不允许调用。**逐会话领域配置和普通任务之间的可编程通信，尚未找到明确的官方接口合同。** 这是该适配仓库首先要解决的问题。[Skill](https://zcode.z.ai/en/docs/skill)、[Plugin](https://zcode.z.ai/en/docs/plugin) |
| **Grok** | dashboard 有查看、回复、进入普通会话的基础。现有子 Agent 消息工具仍限自己的活动 child；需要补证普通会话通信及逐会话配置路径。[界面](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/23-dashboard.md)、[消息边界](https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/16-subagents.md) |

### 我建议明确下来两点

**1. 会话创建时绑定领域，域内 Skill 正文按需加载。**

跨领域新建会话并传递必要交接信息。不要把“工作过程中热切换整套 Plugin、Skill、MCP”设为所有适配器的必备实现方式；DeepSeek 就只允许空会话切换 preset。

**2. 七个适配仓库共享内容，各自维护接入。**

- **共享资产：** 各领域 Skill 包、各自独立的知识库、remote-dev 和知识引擎。
- **适配仓库：** Plugin 打包、领域配置、会话创建与恢复、消息、原生界面接入、版本兼容和验收。
- **共同标准：** 两边都能持续接受人的指导，领域内容不会自动串入其他会话，交接后能够继续工作。

建议先用 **DeepSeek Harness 和 Claude Code** 做两个领域的完整验证，Codex 紧随。

| 风险 | Harness | 主要原因 |
|---|---|---|
| 相对低 | **Claude Code** | 独立会话通信、可交互界面和启动配置的组合路径最明确 |

| 中高 | **Grok** | 普通会话通信、逐会话领域配置尚未形成已证实的组合 |
| 高 | **Z Code** | 关键扩展接口是否开放还不明确，可能需要上游配合 |

其中两项需要保留：

- **Kimi：** Web API 的部分工具/MCP 配置字段明确尚未生效，不能只靠写适配器就假定能使用。[官方说明](https://www.kimi.com/code/docs/en/kimi-code-cli/reference/server-api.html)

**所以，Claude Code、Codex、DeepSeek 可以作为主线推进；Cursor、Kimi、Grok、Z Code 先各做一个接口验证。** DeepSeek 可能需要写更多代码，但实现路径较可控；Z Code 的风险包含“我们是否拿得到所需接口”。

这是基于现有机制证据的工程判断，双会话实测后才能进一步降低风险等级。
