RecomputeScheduler 本身在真实 KV 压力下可以正常退出重计算流程。实际发现的是示例 P/D proxy 在重计算续跑时存在完整性问题：

- token-ID prompt 与字符串拼接导致 `list + str` 异常。
- retry 缩小 `max_tokens` 后未同步处理 `min_tokens`。
- 把任意 HTTP chunk 当成单条 SSE，多个事件合并时会漏掉 recompute 信号。
- retry 后 usage 和 prompt metadata 只反映最后一段。

已修复：

- 使用流式返回的 token IDs 精确重放 prompt。
- tokenized prompt 强制要求 `return_token_ids=true`。
- 同步收缩 `min_tokens/max_tokens`。
- 按 SSE line 解码。
- 聚合多段 usage，并恢复原始 prompt metadata。
- 补充 recompute retry、terminal、DONE 的结构化日志。
