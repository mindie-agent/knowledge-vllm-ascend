### 生命周期契约

| 场景 | 可保证的行为 |
|---|---|
| 初始完整加载 | 预分配 Parameter 与 packed 结果 shape/dtype/device 一致，`prefer_copy=True` 原地填充，图捕获前地址固定。 |
| 完整 q/k/v checkpoint reload | q-conv 因派生参数未出现在 checkpoint 中会延迟到 finalize；届时三路源权重都已恢复，完成 repack。layerwise reload 再复制回保存的 kernel Parameter，最终 `data_ptr` 不变。 |
| kernel-format direct reload | 必须携带派生参数名，例如 `...q_conv1d.conv_weights_t_packed`；core 直接 `get_parameter(name).copy_()`，地址不变。只更新 raw q/k/v 不会触发 post-process，会造成不一致。 |
| partial checkpoint-format 更新 | 最小方案不承诺。单独更新 q/k/v 任一路时，其他路可能仍为 meta，raw/packed 会失配；需要额外 reload 协议才能支持。 |
| ACLGraph | `data_ptr` UT 只能证明必要条件；充分证明仍需一次 capture → reload → 同一图 replay，并核对输出与 eager。 |

### v0.25.1 核实

已核实 v0.25.1 存在 `replace_parameter(..., prefer_copy=True)`，实现与当前 core 一致：仅在旧参数和新数据的 shape、dtype、device 全部相同时执行原地 `copy_`。
