### Motivation.

Initial Kimi K3 support landed in `releases/v0.26.0rc` through #12950. This roadmap tracks Kimi K3 capabilities by target branch and feature area. A checked item means the capability is available on the branch named in that section; release-branch completion does not imply availability on `main`.

Kimi K3 integration into `main` begins only after main2main advances to an upstream vLLM revision containing the required Kimi K3 changes.

### Proposed Change.

#### Hardware-specific execution matrix

| Capability | A2 (Ascend 910B) | A3 (Ascend 910C) | A5 (Ascend 950) |
| --- | --- | --- | --- |
| SiTU operator | **DequantSituQuant** | **DequantSituQuant** | **SituMxQuant** |
| MoE quantization format | INT W4A8<br>INT4 weights / INT8 activations | INT W4A8<br>INT4 weights / INT8 activations | MXFP W4A8<br>MXFP4 weights / MXFP8 activations |

In the A5 W4A8 MXFP path, MXFP4 is the weight format; `SituMxQuant` quantizes the SiTU output activations to MXFP8.

## 主要改写

1. 长序列：

   - 原：`Support Kimi K3 128K and 1M sequence lengths`
   - 新：`Support up-to-1M long-sequence inference`

   新版更简洁，但不再显式写 Kimi K3 和 128K。作为 roadmap，我觉得新版可以接受。

2. Multistream：

   - 原：`Enhance Kimi K3 shared-expert multistream overlap.`
   - 新：增加 `to reduce the kernel conflicts`

   增加了优化目标，但 `kernel conflicts` 不够自然，建议改成：

   > Enhance Kimi K3 shared-expert multistream overlap to reduce kernel contention.

3. A5 shared expert：

   - 原：`W4A8 MXFP shared experts`
   - 新：`W4A8 MXFP4 shared experts`

   新版把权重格式写得更具体，但容易把整个量化方案名称写成 MXFP4。更准确的写法是：

   > Support Kimi K3 W4A8 MXFP shared experts with MXFP4 weights on A5.

4. NoPE MLAPO：

   - `including non-contiguous...` 改成 `adapting non-contiguous...`

   语义基本不变，但 `adapting` 反而不如原文自然。建议用：

   > including support for non-contiguous PagedAttention caches...

5. MLA query heads：

   - 原：`original query-head count`
   - 新：加入 `(head_num=96)`

   这是实质性精化，但存在歧义：96 是模型全局 head 数，算子实际看到的可能是 TP-local head 数。建议保留原写法，或写成：

   > Run MLA decode with the original query-head count instead of power-of-two padding.

6. FlashDecoding：

   只是调整语序，没有语义变化。

7. DSpark 术语：

   - `GQA DSpark` → `DSpark drafter with GQA`
   - `MLA DSpark` → `DSpark with MLA drafter`

   方向是好的，更明确 GQA/MLA 指的是 drafter 类型。不过不建议写 `GQA-drafter`、`MLA-drafter`，应去掉连字符：

   > Fix Kimi K3 DSpark GQA-drafter correctness...

   最好改成：

   > Fix correctness and accuracy issues in the Kimi K3 DSpark GQA drafter under long context and Prefix Cache...

8. Delta-gated fusion：

   - 原：`Kimi K3 delta-gated fusion`
   - 新：`Kimi K3 MLA delta-gated fusion`

   增加了 MLA 范围。如果这个 fusion 确实只属于 MLA，这个修改更准确，建议保留。

9. Main 的上下文描述：

   - `128K/1M context` → `up-to-1M context`

   与 release 部分保持一致，可以接受。

## 我的结论

这次润色中值得保留的主要是：

- `up-to-1M` 的表达；
- 将 GQA/MLA 明确为 DSpark drafter 类型；
- 将 delta-gated fusion 限定为 MLA；
- 给 shared-expert multistream 增加优化目标，但应使用 `kernel contention`。

不建议直接接受的部分是：

- 删除 MoE communication matrix；
- 删除 A2 896/512 限制说明；
- 删除 sparse offload；
- 删除 MRV2 的 A2/A3/A5 通信策略；
- `head_num=96` 的直接写法；
- `W4A8 MXFP4 shared experts` 和 `GQA-drafter` 这类不够准确的术语。

因此它不是单纯的英文润色，也包含几处 roadmap 范围缩减。当前 issue 我没有修改。
