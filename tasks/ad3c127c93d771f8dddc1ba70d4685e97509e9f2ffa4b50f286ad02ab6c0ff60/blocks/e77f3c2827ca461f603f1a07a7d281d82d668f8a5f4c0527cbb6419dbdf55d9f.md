对，这里不会影响 fused MoE 的方案。我前面把“token 维 AllGather”和“不同 EP rank 的专家部分结果求和”混在一起了；当前讨论的是前者。

因为 linear 和 RMSNorm 都没有切分，并且逐 token 独立计算：

\[
\operatorname{AllGather}(F(X_r))
=
F(\operatorname{AllGather}(X_r))
\]

其中 \(F\) 可以是完整权重的 linear 或 RMSNorm。RMSNorm 只在 hidden 维归约，AllGather 发生在 token 维，因此数学上等价。

当前 K3 FlashComm 修改也没有改动：

- fused MoE 的路由与 expert map
- routed/shared expert 的计算
- EP 通信后端选择
- expert 输出的归并方式

实际 diff 只涉及 KDA/MLA 的 token 布局、MLA gate 和 K3 learned residual。最多可能因为不同 token batch shape 触发不同 GEMM kernel，产生极小的浮点舍入差异，但这不是 MoE 语义或方案问题。

所以当前开关 FlashComm 后的 token 不一致，不应该沿 fused MoE 方向修改；应继续定位 decode 阶段的 KDA/MLA 状态或 ACLGraph replay 路径。

### assistant:final_answer
只读审计结论：

1. 当前 eager 下 FlashComm off/on 已经不一致，因此暂时不应继续归因 ACLGraph。
2. 没发现首层 token 布局、KDA state、MoE 或 final gather 存在明确语义错位。
3. 用户关于 token 始终是 dim0 的理解正确。DeepSeek V4 的 HC 张量也是 `[N, hc_mult, H]`，通信并不要求严格二维。

明确需要整理的是框架 helper：

- `maybe_chunk_residual` runtime 对 3D 张量的 `F.pad(..., (0,0,0,pad))` 会 pad dim1，而不是 dim0。
- fake 固定返回 `empty_like(x)`，不能保留 residual 的 trailing dimensions。
- 应改成通用 dim0 padding，fake shape 使用 `(x.shape[0], *residual.shape[1:])`。
- 随后 K3 可直接调用：
  `maybe_chunk_residual(attention_output, block_residual)`
  不再需要 K3 私有的 squeeze/unsqueeze 处理。

但当前 DP1 runner 已预先将 token 补齐到 TP16 倍数，`pad_size == 0`，因此这项框架清理不会直接修复目前 eager 精度分叉。

各模块判断：

- 首层 global→local：布局和 rank 顺序正确。
- KDA：后续层在全部投影前恢复 global token，active token 与 state metadata 的顺序正确。
- learned residual：RMS、score projection 和 block mixture 都逐 token，切分前后数学等价。
- MLA gate：这里不能套用“linear 未切分”的判断。`g_proj` 是 ColumnParallel、不同 TP rank 持有不同 head/output shard，因此必须先 gather hidden token，再投影；当前实现正确。
- MoE：当前 A3 EP16 使用 MC2/ALLTOALL，K3 没有改变其通信语义；shared/routed transform 都逐 token。
- final gather：rank-contiguous chunk 与 reduce-scatter 布局一致。

当前最可能是数值路径差异被 recurrent KDA 放大：

- off/on 同时改变 GEMM 的 M：
  - decode：1 → 16
  - text prefill：299 → 304
  - image prefill：262 → 272
- row parallel 从 BF16 all-reduce 改为 reduce-scatter。
- shared expert 从 TP shard 改为完整 replicated 权重。
- 这些局部误差进入 KDA recurrent state 后可逐 token 累积。

建议最小化定位：

- 分别用 1/2/3/4/5 层权重启动：
  - 1 层：首层 KDA、global→local、final gather
  - 2 层：首次加入 KDA+MoE
  - 4 层：首次加入 MLA gate
- 用 16 个并发请求，让 off/on 的 M 都为 16，排除 padding/GEMM shape 差异。
- teacher-force 相同 token prefix，依次比较：
  - layer 0 active q/k/v/gate
  - layer 0 recurrent/conv state
  - o_proj 后将 local all-gather 的结果
  - 首层 block residual
  - layer 1 gather 后 hidden
  - 每层 decode 后的 KDA state

另外，仓库中的 Qwen3.5 FlashComm 用例主要是运行 smoke 或任务集精度阈值，并没有证明 off/on 逐 token 完全一致。
