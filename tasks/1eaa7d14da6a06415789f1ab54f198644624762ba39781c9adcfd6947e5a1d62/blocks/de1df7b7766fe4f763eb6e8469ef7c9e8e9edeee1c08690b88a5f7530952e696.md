### assistant:final_answer
当前方案是：**一次初始化，新会话准备一次；工作目录和组件版本按任务固定，知识与有效成果共享复用。** 五个 Agent 客户端共用这套核心，只保留少量客户端接线。

1. **首次使用：确认身份，一次配齐。**  
   Agent 询问一次个人 GitHub ID，创建或复用个人 Fork，设置个人 `origin` 和官方 `upstream`，然后配置已安装的 Codex、Cursor、Claude、Grok、Kimi 的 hooks、MCP 和短项目提示。用户不必主动调用初始化 Skill。

2. **新会话：自动取得主仓版本并准备 worktree。**  
   原生 hook 先把客户端会话关联到 VAWS task。客户端已经准备好 worktree 时直接复用；否则，项目短提示让 Agent 首个仓库动作执行一次 `vaws_start`。它负责：
   - 检查主仓默认分支，选定精确提交；
   - 创建独立 worktree，绑定任务源码；
   - 复用或安装该提交锁定的组件组合，并快进个人 Fork；
   - 返回工作目录和准备结果。

   **组件跟随主仓锁定的组合，不分别追各组件的最新分支。** 没有五分钟代码轮询，也不在工作中更新。Resume 保留原任务的目录和版本。

3. **执行时：稳定入口路由到任务自己的环境。**  
   MCP 入口根据原生任务身份选择对应的组件进程。因此同一个客户端连接可以服务新旧任务：新任务用新环境，旧任务继续用旧环境，Agent 不需要手动重连。  
   本地文件/Git 使用原生工具；远端 I/O 交给 remote-dev；容器、NPU、服务和资源队列交给 Coordinator；监控交给 vaws-top。轻量任务不会因此启动远端资源。

4. **知识库：共享内容和索引，自动复用已有总结。**  
   同一工作区的不同客户端、worktree 共用知识配置、候选内容、索引和兼容模型服务。查询按需进行；结束 hook 直接保存正常最终答复，不要求再写一份总结。知识始终是参考。  
   **代码版本按任务固定，知识内容可以继续更新。** 当前公共知识语料通过语料仓库的 Release 分发，这与代码跟随主仓 main 是两条独立链路。

5. **共享服务器：身份、容器和协调由工具处理。**  
   GitHub 身份自动带入任务，同一用户默认复用 `vaws-<github-login>` 容器。任务结束释放自己的进程和资源，保留容器与有效成果。留言复用现有 Coordinator 的宿主机消息库，随正常工具调用收取，无需 Agent 轮询；目前不会主动唤醒离线 Agent。权重、算子编译产物和兼容环境直接跨用户复用，不增加个人/公开分类和共享审批。

Agent 的日常额外成本主要是：**普通新会话的一次准备调用，以及后续工具使用返回的目录；Kimi 还需携带已有 context。** 没有每个任务的身份登记、更新检查、收件轮询或重复总结。

当前需要明确的边界是：准备器绑定了工作目录和源码，但原生 UI、工具默认 cwd 可能仍在母目录，Agent 要显式使用返回路径；共享 root 下也只提供归属识别和工具内资源检查，无法阻止绕过 VAWS 直接操作机器。
