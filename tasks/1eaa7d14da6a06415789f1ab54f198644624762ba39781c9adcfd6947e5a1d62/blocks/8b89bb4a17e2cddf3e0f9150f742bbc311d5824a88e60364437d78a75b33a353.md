| 部分 | 工具内部行为 |
|---|---|
| 身份 | 初始化确认一次，保存现有 `login/github_user_id`；运行入口自动读取，禁止静默回退成服务器 `root`。Agent 不反复传 username。 |
| 容器 | 默认 `vaws-<GitHub用户名>`，统一规范大小写；按完整名字定位，再用准确 container ID 与当前 execution 核对。禁止模糊前缀匹配。停止任务只停止其进程和租约，保留用户容器。 |
| 名字变化 | GitHub 改名、版本升级、建立新编辑副本不自动重命名已有容器；工具保留既有运行记录。异常冲突才返回具体差异。 |
| 消息 | 发送者、任务引用、线程、时间、去重、游标自动填写；相关消息随现有 `run/status` 或内部通知到达，不要求手动 ACK 或另写总结。Agent 只判断业务上是否让出资源、何时让出。 |
| 资源接续 | coordinator 内部等待释放、检查真实进程/NPU 状态并推进原请求；留言接受不等于资源已经转移，也不转交别人的容器控制权。 |
| 复用 | 自动查兼容产物、模型和环境，展示来源及实际复用结果；涉及修改时复制到自己的任务目录。不要默认接管他人的可写目录或活动容器。 |

1. **身份尚未进入运行调用链。** [task_client](<redacted:local-path:24b6efa4361b>:43) 只转发 context/kwargs；coordinator launch 也没有读取 GitHub 配置。后续必须由 coordinator 共同入口承接，覆盖直接 MCP、Python 和 Skill，不能只补 wrapper。
2. **更新必须继承容器身份。** [copy_workspace_identity](<redacted:local-path:dbbc107474e3>:24) 当前只复制三个字段；若加入既有容器命名映射，也要继承，不能更新后重新推导 owner、合并任务或重建容器。

验收聚焦两名用户、同为 root：自动进入各自容器；名字相似也不串；停止自己的 execution 不影响对方；离线消息恢复不重复；资源释放后原排队请求继续；新副本和新 Release 保留身份与活动运行。无需增加强身份基础设施验收。
