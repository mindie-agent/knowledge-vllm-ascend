### 5. Scheduler 唯一新增的实质行为：Mooncake P-side

commit 在 `Scheduler.schedule()` 中只额外做了：

```python
if (
    self.use_dspark
    and request.kv_transfer_params is not None
    and request.kv_transfer_params.get("do_remote_decode") is True
):
    new_computed_blocks = self.kv_cache_manager.empty_kv_cache_blocks
    num_new_local_computed_tokens = 0

    ...get_computed_blocks(request)
```

目的是 P-side 必须完整 forward prompt，生成所有 aux hidden 和 draft KV，不能先吃本地 prefix hit。

运行时无需复制整个 `schedule()`。更安全的 monkey-patch：

- 包住 scheduler `__init__`，把 `speculative_config.method == "dspark"` 标记到其 `kv_cache_manager`。
- 包住 `KVCacheManager.get_computed_blocks(request)`：
  - 标记为 DSpark 且 `do_remote_decode=True` 时返回 `(empty_kv_cache_blocks, 0)`
  - 其他情况调用原方法。

这个落点同样覆盖复制了 `schedule()` 的 Balance/Recompute/Profiling scheduler，且仍发生在 connector 的 `get_num_new_matched_tokens()` 之前。
