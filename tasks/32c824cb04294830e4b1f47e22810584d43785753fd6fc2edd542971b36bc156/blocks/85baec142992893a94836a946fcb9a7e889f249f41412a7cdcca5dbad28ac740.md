### 主要问题

- **[P1] collection 校验的 DB 与实际分析的 DB 可能不是同一个。**  
  collection 明确按 mtime 选最新 DB，但分析侧在 [sources.py](<redacted:local-path:0586a8f3ac45>:96) 中按文件名排序并返回第一个；同时 `--manifest` 只取 `remote_profile_root`，没有使用 manifest 记录的精确 `db_path`。同一 rank 目录存在多次导出的 DB 时，可能校验新 DB、静默分析旧 DB。建议直接消费 manifest 的 per-rank `db_path`，或统一成 newest-by-mtime 选择器并加回归测试。

- **[P1] 混合层数 inventory 可能被错误判定为 `ok`。**  
  [analysis_summary.py](<redacted:local-path:7ce851232363>:269) 使用 `any(expected_layers in values ...)`。例如所有 rank 都是 `[60, 61]`、预期 61 时，会同时得到 `layers_match=true`、`per_rank_consistent=true`、最终 `status=ok`；但 segmenter 的契约是在 [segment.py](<redacted:local-path:8141539a9b03>:1924) 校验每个 complete step。HTML payload 也复制了同样逻辑。应要求所有 complete-step count 命中 accepted targets，或直接传播 `layer_count_validation.status`。

- **[P2] 最终 JSON 的分析模式被覆盖。**  
  [profile_analyze.py](<redacted:local-path:ba29e1351a7b>:952) 同一 dict 写了两次 `"mode"`：`args.mode` 随后被 `target["mode"]` 覆盖。调用 `--mode fast` 最终可能输出 `"mode": "session"`，破坏 agent-first 输出契约。建议拆成 `analysis_mode` 与 `target_mode` 并补 wrapper 输出测试。

- **[P3] K3 fingerprint 中存在重复 JSON key。**  
  [model_fingerprints.json](<redacted:local-path:ff68d99e0124>:395) 连续定义两次 `field_hints`。目前后一个是前一个的超集，没有立即丢值，但标准 JSON parser 会静默覆盖，验证器也发现不了后续漂移。
