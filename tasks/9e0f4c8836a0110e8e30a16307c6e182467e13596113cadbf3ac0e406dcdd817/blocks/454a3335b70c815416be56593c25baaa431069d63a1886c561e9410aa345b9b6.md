  ```python
  view_5 = aten.reshape(unquantized_gemm_13, [16, 6, 128])

- 生产源码对应 `vllm_ascend/ops/kimi_kda.py:182`，即 layer 1：

  ```
- `unquantized_gemm_13` 是 `f_b_proj` 输出。运行时元素数 `1572864 = 2048 × 768`，正确 shape 应为：
  ```text
  [2048, 6, 128] → [1, 2048, 6, 128]
  ```
  不是 `[16, 6, 128]`。

原因是 FlashComm 首层在编译图内部完成 global→local：

```text
编译样例：global 16 → RS local 1 → 下一层 AG global 16
实际 profile：global 2048 → RS local 128 → 下一层 AG global 2048
```

首层 RS 产生的派生动态维在 ACL/AOT artifact 中被静态化成编译样例值。关闭 FlashComm 的 cache `02b074bf63` 同一位置保持 `[arg1_1, 6, 128]`，因此不是权重或 head 参数问题。
