### GPQA 请求怎么构造

每道题拼成一个 user message：

```text
Answer the following multiple choice question. The last line of your response should be of the following format: 'Answer: $LETTER' (without quotes) where LETTER is one of ABCD. Think step by step before answering.

{question}

A) {A}
B) {B}
C) {C}
D) {D}
```

对应请求体在 [run-gpqa-nightly-compatible.py](<<redacted:local-path:b8dd889167fe>/run-gpqa-nightly-compatible.py:63>)：

```json
{
  "model": "kimi-k3-w4a8",
  "messages": [
    {
      "role": "user",
      "content": "<上面的完整 GPQA prompt>"
    }
  ],
  "max_tokens": 65536,
  "temperature": 1.0,
  "top_p": 0.95,
  "top_k": 20,
  "min_p": 0.0,
  "presence_penalty": 1.5,
  "repetition_penalty": 1.0,
  "stream": false,
  "chat_template_kwargs": {
    "thinking": true
  }
}
```

### Chat template 的作用

服务启动参数里有：

```bash
--chat-template <redacted:user-path:f35680a745ca>
```

所以 curl 只传 `messages`。服务端模板 [k3-chat-template.jinja](<<redacted:local-path:b8dd889167fe>/k3-chat-template.jinja:1>) 会：

- `thinking=true`：注入 `thinking_effort=max` 的 system message，并以 `<|open|>think...` 开始生成。
- `thinking=false`：不注入 thinking system message，直接以 `<|open|>response...` 开始生成。
- 不传 `chat_template_kwargs` 时，这份模板默认 `thinking=true`。

### GPQA 后处理

后处理并不是额外的模型参数，而是客户端评分逻辑：

```python
content = response["choices"][0]["message"]["content"]
match = re.search(r"(?i)ANSWER\s*:\s*([A-D])", content)
prediction = match.group(1).upper() if match else None
```

也就是从最终 `content` 中提取 `Answer: A/B/C/D`，再和经过选项重排后的标准答案比较。相关代码在 [run-gpqa-nightly-compatible.py](<<redacted:local-path:b8dd889167fe>/run-gpqa-nightly-compatible.py:95>)。

如果只是查看回复：

```bash
... | jq -r '.choices[0].message.content'
```

如果要提取 GPQA 答案，可以继续：

```bash
... |
jq -r '.choices[0].message.content' |
sed -nE 's/.*[Aa][Nn][Ss][Ww][Ee][Rr][[:space:]]*:[[:space:]]*([A-Da-d]).*/\1/p' |
tr 'a-d' 'A-D'
```

这份模板的核心逻辑确实来自 K3 自带 tokenizer：

```text
thinking=true
    → 注入 thinking_effort=max
    → 打开 <|open|>think<|sep|>

thinking=false
    → 打开 <|open|>response<|sep|>
```

普通消息被编码为：

```text
<|open|>message role="user"<|sep|>
用户内容
<|close|>message<|sep|><|end_of_msg|>
```

有个需要注意的地方：这是一份“简化兼容模板”，不是 K3 官方 Python `apply_chat_template()` 的完整等价实现。它足够覆盖当时 GPQA 的单轮纯文本请求，但没有完整实现：

- tools/tool results
- `response_format`
- 带 `name` 的消息
- 历史 assistant reasoning/response 分段
- K3 原生多模态内容渲染的全部细节

所以结论是：当时 GPQA 使用的是我们手写的、参考 K3 `encoding_k3.py` 的简化模板。对于 GPQA 单轮文本基本符合原生格式；如果要作为正式 K3 Serving 方案，最好让 vLLM 直接兼容 K3 的 `apply_chat_template()`，或者生成一份与其完整等价的 Jinja，而不是长期依赖当前这份简化文件。
