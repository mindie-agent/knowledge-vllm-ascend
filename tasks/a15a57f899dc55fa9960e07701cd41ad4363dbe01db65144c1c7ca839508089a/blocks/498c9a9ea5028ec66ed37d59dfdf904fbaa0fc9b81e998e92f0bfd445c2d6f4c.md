逐项对照：

| 项目 | SGLang `02a924b` | 当前 vLLM Ascend | 判断 |
|---|---|---|---|
| target hidden | 第 7/23/51/67/83 层运行完后，用下一层 attention-residual mixer 物化下一层 pre-RMSNorm 输入 | 配置层号 `+1` 为 `[8,24,52,68,84]`，在这些层入口用该层 mixer 物化 | 数学等价；必须保留 `+1` 和 materialized capture |

| 7-step Markov | anchor 放第 0 列，循环 7 次，step k 用上一步 token 加 Markov bias | `[B,8]` buffer，第 0 列 seed，循环写 1…7 | 对齐 |
| draft head | checkpoint 不带 embedding/lm_head，运行时共享 target embedding/lm_head | 设计上也应共享 | 必须运行时检查真实共享，错误 placeholder/head 会直接压低首轮接收率 |

| KDA commit | verify 不改 persistent state；每步写 scratch，提交 `commit_len-1` | 每步状态写 state pages，选 `accepted_count-1` | 公式对齐 |
| conv commit | 每步 rolling window 写 scratch，按最后正确 step 提交 | speculative state 长度 `3+7=10`，选 `[L-1:L-1+3]` | 公式对齐，实际布局尚缺算子级 oracle |

KDA/conv 的正确计数定义是：

```text
x = 接收的 draft 数，范围 0…7
L = commit_len = x + 1，包含 target bonus，范围 1…8
正确状态 = verify scratch/state 的第 L-1 步
```

所以最危险的 off-by-one 是把 `L` 当成 drafts-only：

- 用 `L` 取状态：多前进一步；
- 先把 `L` 减成 drafts 数再减一次：少前进一步；
- 当前 `count(sampled_token_ids != -1) - 1` 在“有效输出包含 bonus”的前提下是正确的。

尤其重要：24.23% 的精确启动脚本是 prefix-cache `off`，因此 `postprocess_mamba_align` 不在该基线关键路径上。align-copy 即使有问题，也解释不了这次 24.23%。优先级应放在：

1. 首轮 hidden capture 数值是否与 SGLang 相同；
2. draft embedding/lm_head 是否真实共享 target 参数；
3. anchor/query 构造与 target logits 对齐；
4. 只有“第 1 轮正常、第 2 轮开始崩”时，再集中查 KDA/conv 状态提交。

接收率口径也已对齐。SGLang 的 accept length 包含 bonus；draft accept rate 为：

```text
(AL - 1) / 7
```

模型卡 GSM8K `AL=5.6660`，即 `66.6571%`；当前 vLLM `24.23%` 对应 `AL=2.6961`，差约 `42.43` 个百分点。两者只有在相同 prompt、采样和请求集下才能做最终定量比较。

建议的最小验证 probe：

- 固定一份 pre-verify KDA/conv state，输入 anchor + 7 drafts。
- 并行 verify 一次，再独立串行执行 8 步。
- 对每个 `L=1…8` 验证：
  - KDA `state_indices[L-1] == serial_state_after_step(L-1)`；
  - conv `[L-1:L-1+K-1] == serial_window_after_step(L-1)`；
  - 从两份选中状态继续跑同一个 token，输出完全一致。
- 运行时按 verify round 分桶记录接收率：round 0 与 round ≥1。round 0 已低就排除状态提交；round 0 正常、后续坍塌才指向 KDA/conv。

当前判断：没有证据表明 `accept_count/bonus/block_size=7` 的现有公式存在直接 off-by-one；最值得先证伪的是 hidden capture 数值和共享 embedding/lm_head，KDA/conv 用上述 L=1…8 oracle 收口。
