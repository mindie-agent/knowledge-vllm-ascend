### 3. 精度硬门槛

Greedy speculative decoding应与非投机解码一致；vLLM也把 greedy equality作为 lossless 验证。[vLLM lossless 说明](https://docs.vllm.ai/en/stable/features/speculative_decoding/#lossless-guarantees-of-speculative-decoding)

建议分三层：

1. 四 DP rank 的 `2+2` gate 必须 `4/4`，无 `None`、乱码、重复 `!!!`。
2. 现有 16 道短答案集，执行 `--mirror-ranks --repeats 2`，必须 `128/128`；四种 `--hot-rank` 各跑一次也必须全过。现有脚本见 [short accuracy gate](<<redacted:local-path:b8dd889167fe>/validate-k3-dspark-short-accuracy-dp4.py:19>)。
3. `temperature=0` 的固定 prompt 集上，DSpark 与 target-only 的 token IDs、finish reason 必须逐项一致。
4. 完整 GPQA-Diamond：
   - 198/198 有响应；
   - `errors=0`、`missing=0`、`unparsed=0`；
   - 不低于已验证 target-only 的 `181/198, 91.41%`；
   - 若用确定性采样，则要求 198 项预测与 target-only 完全一致。

生产 GPQA runner 当前使用 `temperature=1/top_p=0.95`，不适合要求逐 token 完全相同；该腿用于精度分数，另加 `temperature=0` 腿验证严格 lossless。

### 4. 逐位置、Prefix cache 和 DP4 门槛

每个 rank、每个实验腿至少收集 `1000 drafts`。最差情况下单个比例的 95% 误差约为 ±3.1 个百分点，因而 5 pp 是合理的异常边界。

逐位置：

- 计数必须严格嵌套，不能出现后位计数高于前位。
- `accepted_tokens == Σ accepted_per_pos` 必须精确成立。
- 相对基准腿，各位置下降不得超过 5 pp。
- `(L_test-1)/(L_reference-1) ≥ 0.95`。
- 如果位置 0 正常、位置 1～6 快速坍塌，优先检查 Markov head、token 顺序或 draft KV；若七个位置整体下降，优先检查 aux hidden state/权重加载。

Prefix cache：

- 每个 DP rank 分别跑 cold → warm → reset-cold。
- cold/reset-cold hits 必须为 0，warm hits 必须大于 0。
- 三腿输出必须完全一致。
- `(L_warm-1)/(L_cold-1) ≥ 0.95`，逐位置差不超过 5 pp。
- 现有 [prefix validator](<<redacted:local-path:b8dd889167fe>/validate-k3-dspark-prefix.py:143>) 只要求 accepted token `>0`，这不足以验收；应增加上述阈值。

DP4：

- 每个 rank 的 `(L_rank-1)` 不得低于四 rank 中位数的 95%。
- mirrored、hot-rank、混合长度/batch shrink 三种负载均必须 100% 正确。
- 热 rank 压测结束后，紧接一轮四 rank 镜像请求，排除 dummy replay 或 KDA/GDN 状态污染。
- 任何单 rank 重复 `!`、`finish_reason=length`、acceptance 突降都直接失败，不能用四 rank 平均掩盖。
