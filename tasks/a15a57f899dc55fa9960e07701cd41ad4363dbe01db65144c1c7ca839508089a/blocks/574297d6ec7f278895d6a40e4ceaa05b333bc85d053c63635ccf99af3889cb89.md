### DSpark acceptance counters

Run a fixed deterministic workload first, then inspect the counter deltas:

```bash
curl -fsS http://<<redacted:hostname-numbered:88f09974fb13>_LOCAL_IP>:<SERVICE_PORT>/metrics |
awk '
$1 ~ /^vllm:spec_decode_num_draft_tokens_total/ {
    draft += $2
}
$1 ~ /^vllm:spec_decode_num_accepted_tokens_total/ {
    accepted += $2
}
END {
    if (draft == 0) {
        print "No DSpark draft tokens were recorded."
        exit 1
    }
    printf "accepted=%d draft=%d acceptance=%.2f%%\n",
           accepted, draft, 100 * accepted / draft
}'
```
```

核对出的兼容点：

- `--tokenizer-mode kimi_k3` 不能省。当前 pinned core 不会像最新 vLLM upstream 那样自动为 K3 选择该模式；显式配置后由 tokenizer 的 Python XTML encoder 渲染，因此不需要任何 `--chat-template` 路径。
- 官方页面仍使用 `vision_chunk`，但当前上游对齐后的实现注册的是 `image`；公开命令应使用 `{"image":0}`。
- 当前 GQA DSpark 是 Ascend model runner v1 路径，显式设置 `VLLM_USE_V2_MODEL_RUNNER=0` 最稳妥。
- `enable_reduce_sample` 必须为 `false`，`lmhead_tensor_parallel_size` 必须为 `0`，draft sampling 必须为 greedy。
- `enable_fused_mc2=1` 会在配置解析时强制关闭共享专家多流，因此这里必须保持 `0`。
- `[16]` 是当前单请求 DSpark target verification 的已知图桶。若评论准备宣称更高并发，需要先实测后再增加 8-token verification 宽度对应的图桶。
