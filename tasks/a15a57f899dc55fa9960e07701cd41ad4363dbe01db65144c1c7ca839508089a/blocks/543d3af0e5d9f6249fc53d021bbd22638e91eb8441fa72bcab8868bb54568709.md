### 最可能的“低接收率”来源

1. **指标口径可能被误读**

   vLLM 的 Mean acceptance length 定义为：

   `1 + accepted_draft_tokens / num_drafts`

   模型卡的综合参考是 `temperature=0` 时 3.85。换算成七个 draft token 的纯 draft 接收率只有：

   `(3.85 - 1) / 7 = 40.7%`

   PR 所在代码的 DFX `approx_accept_rate` 还把 bonus token 和七个 draft 一起按 8 个槽计算，对应约 `3.85 / 8 = 48.1%`。看到 40%～50% 不一定意味着异常，必须先确认反馈说的是“接收长度”还是“接收率”。[模型卡基准](https://huggingface.co/Inferact/Kimi-K3-DSpark#speculator-acceptance)

2. **非零温度的推荐采样路径尚不支持**

   PR 的 `AscendDSparkProposer` 明确拒绝 `draft_sample_method=probabilistic`，只能 greedy；Ascend block verification 也尚未实现。[proposer 代码](https://github.com/vllm-project/vllm-ascend/blob/258ce51403f3485ebb353dd0b66ebe6d5af06e7e/vllm_ascend/spec_decode/dspark_proposer.py#L35-L39)

   但模型卡在 `temperature=1/top_p=0.95` 下使用的是 `probabilistic + block`。因此只能先比较：

   - `temperature=0`
   - `draft_sample_method=greedy`
   - 不配置 block rejection

3. **`enable_reduce_sample=true` 与 DSpark 不兼容**

   该分支会绕过逐 token 的 Markov bias 采样逻辑，按普通 LM head 做 argmax；严重时应直接形状报错，未报错也不能作为有效接收率结果。首轮必须确认 `enable_reduce_sample=false`。

### 1. 指标口径

设每轮提出 7 个 draft token，`N` 为 draft 轮数，`A_j∈[0,7]` 为第 `j` 轮实际接收的 draft 数：

- Mean acceptance length：`L = 1 + ΣA_j / N`
- Draft acceptance rate：`R = accepted_tokens / draft_tokens`
- 固定每轮七个 draft 时：`R ≈ (L - 1) / 7`
- 第 `i` 位无条件接收率：`p_i=P(A≥i+1)`
- 必须满足：`1≥p_0≥p_1≥...≥p_6≥0`
- 恒等式：`L = 1 + Σp_i`

vLLM 明确把 bonus token 计入 Mean acceptance length，并公开逐位置计数器；SGLang 的模型卡口径同样是“生成 token 数 / verify 次数”。[vLLM 指标实现](https://github.com/vllm-project/vllm/blob/542a8fad6da059a0fd4a8b0a03b4476e9ec9b66a/vllm/v1/spec_decode/metrics.py#L88-L99)、[SGLang 指标实现](https://github.com/sgl-project/sglang/blob/983e4aa18d7e8746d3ef357ad9f8c8d757a3de5b/python/sglang/srt/managers/scheduler_components/metrics_reporter.py#L765-L775)
