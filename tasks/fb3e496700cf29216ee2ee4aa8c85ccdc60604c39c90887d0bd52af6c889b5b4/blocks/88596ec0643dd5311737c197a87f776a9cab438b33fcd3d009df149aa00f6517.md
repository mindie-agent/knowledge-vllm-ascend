> Kimi-K3 官方或 vLLM 上游 reference

### 数值证据重新标注

用真实 layer-12 权重得到：

| Shape | AscendC vs 官方预合并 | AscendC vs legacy NPU | 官方 vs legacy NPU |
|---|---:|---:|---:|
| T=16 | 8 mismatches | 23 mismatches | 20 mismatches |
| T=32 | 25 | 53 | 49 |
| T=129 | 93 | 200 | 200 |

AscendC 明显更接近官方预合并实现。原始数据见 [old-precombined-real-layer12-weights.json](<redacted:local-path:bd6fc910bff1>)。

但“公式一致”不等于 BF16 bitwise 一致：T=16 对官方公式仍有 8 个 BF16 mismatch，最大误差 `0.001953125`。算子若声称的是公式一致或 `assert_close` 通过，是正确的；若声称逐 bit 一致，则不成立。

### 为什么测试都通过了

上游测试虽然写成 `F.rms_norm → @ qk_weight`，但使用：

```python
assert_close(atol=8e-2, rtol=3e-2)
```

Ascend 原测试也使用 `atol/rtol=2e-2`。这些容差足以接受上述 BF16 差异，只验证近似正确，不验证 93 层后的 greedy trajectory。

PR #18 的 UT 还 mock 了 `npu_rms_norm`，因此没有覆盖真实 NPU reduction 行为。

### 根因定性

准确的根因应当改为：

> Ascend PR #18 将 Kimi-K3 官方预合并 residual mixer 改成了 `npu_rms_norm + matmul`，形成了一个不同的 legacy 数值轨迹。MLA DSpark 的现有采信率基线建立在这条轨迹上。接入遵循官方/vLLM 上游公式的 AscendC 后，target token trajectory 改变，因而与固定 draft checkpoint 的 acceptance counters 改变。

因此：

- 采信率从 `5.23` 降到 `3.88` 证明 target/draft 对齐发生变化，但不能证明 AscendC 模型语义错误。
- 当前只对 MLA DSpark 回退到 NPU decomposition，本质是 draft-checkpoint 兼容 workaround，不是算子正确性修复。
- 该 workaround 还会使 target 数值语义随 draft 类型变化，长期不够干净。
- PR 评论里“模型 reference 是 `npu_rms_norm + matmul`”“问题在 AscendC RMS/matmul 顺序”的表述需要撤回或改写。

建议下一步先按官方/vLLM 上游语义保留 AscendC，然后用非 speculative 的 target 输出质量、官方实现逐层/logit 对齐和 GPQA 判断正确性；如果现有 MLA draft 确实依赖 PR #18 的数值轨迹，再把 fallback 明确定义为 checkpoint compatibility，后续通过重新对齐或训练 draft 消除。此次只做了只读定位，没有修改代码或 PR。
