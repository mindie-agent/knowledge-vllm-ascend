### 三方实现对齐结果

Kimi-K3 官方模型的 residual mixer 明确写成：

```python
variance = v_fp32.pow(2).mean(-1, keepdim=True)
k = v_fp32 * rsqrt(variance + eps)
score_weight = norm.weight.float() * proj.weight.float()
scores = (k * score_weight).sum(-1)
```

见 [modeling_kimi.py](<redacted:local-path:2d73c0650753>:1119)。它没有调用 `norm(v)` 再做 Linear，而是有意把 norm gamma 和 projection weight 预合并。

当前 vLLM main `d9dac2b3` 也采用同样逻辑：

- [NVIDIA Triton](https://github.com/vllm-project/vllm/blob/d9dac2b3d4cdd57ff2f7c5311bc8aaf3eef3feec/vllm/models/kimi_k3/nvidia/ops/attn_res.py#L102-L139)：先计算 `input_qk_weight = norm_weight * qk_weight`。
- [AMD Triton](https://github.com/vllm-project/vllm/blob/d9dac2b3d4cdd57ff2f7c5311bc8aaf3eef3feec/vllm/models/kimi_k3/amd/ops/attn_res.py#L41-L70)：完全相同。
- [SM100 CUDA](https://github.com/vllm-project/vllm/blob/d9dac2b3d4cdd57ff2f7c5311bc8aaf3eef3feec/csrc/libtorch_stable/kimi_k3/attn_res_kernel.cu#L325-L349)：将 `rms_w * res_w` 缓存在寄存器，再计算 dot 和 inverse RMS。

合入前 Kimi-K3 集成分支 `5a3eba03` 与当前 main 的 NVIDIA、AMD、CUDA AttnRes 文件 blob SHA 全部一致，说明上游合入前后逻辑没有变化。

AscendC 同样如此：

- [resident kernel](<redacted:local-path:c73662844e61>:138)
- [reload kernel](<redacted:local-path:c7bcc9a7886a>:215)

两者均先生成 `scoreWeight = projWeight * normWeight`，再执行 RMS reduction、dot reduction。因此公式契约上，AscendC、Kimi 官方实现和 vLLM 上游是一致的。

### 真正发生漂移的位置

问题来自 Ascend 私仓的 `3d396f2f8`，即原 PR #18：

```text
原始私仓实现 17f905b:
    custom RMS + precombined norm/proj weight

PR #18 3d396f2:
    torch_npu.npu_rms_norm(values, norm_weight)
    torch.matmul(normalized, proj_weight)
```

PR #18 把官方预合并写法替换成了 `npu_rms_norm → matmul`。两者数学等价，但由于 FP32 乘法结合顺序、RMS reduction、dot/matmul reduction 不同，在 NPU 上不保证逐 bit 一致。

随后私仓的 Triton 实现 `e1f4f30cd` 又恢复成了预合并公式。AscendC 也是沿这条官方公式实现的。

所以此前所谓的“pre-operator reference”，其实是：

> PR #18 引入的 vLLM-Ascend legacy NPU decomposition

而不是：
