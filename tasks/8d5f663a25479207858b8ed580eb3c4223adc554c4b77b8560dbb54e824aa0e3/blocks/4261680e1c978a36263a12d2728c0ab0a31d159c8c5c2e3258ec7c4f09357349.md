这些方案共同支持一个方向：**经验应当成为可独立更新、按需读取的知识单位。** 但没有哪一种架构名称，能够自动保证“重要经验不漏、错误结论不进、处理费用足够低”。

尤其需要把两笔成本分开：把长记录整理成经验的成本，以及后续任务读取经验的成本。渐进式检索主要降低后者；这次需要优先解决前者。

**对上一轮“候选经验＋相关证据”的建议，我会补上一个重要限制。**

候选可以来自最终答复、诊断说明、修复说明和用户纠正，能够复用业务任务已经完成的分析。但**候选不能成为唯一入口**：重要的排除过程或结论反转可能只出现在中间，最终回复甚至可能只是“已停止监控”。

这里存在一个基本取舍：如果两份历史的唯一重要区别藏在某个未读片段里，整理器没有读到该片段，就无法区分它们。因此，对任意自由文本，同时要求极少阅读和完整发现所有经验，没有可靠依据。

我建议先建立这个基线：

> **经过安全的机械压缩后，让全部获准的新增公开材料进入一次语义处理；候选用于引导关注，相关证据用于约束结论。**

之后再测选择性阅读能节省多少、会漏掉什么。这样，优化有明确的质量参照。

**具体落地可以沿用现有组件，只扩展整理这条路径。**

**采集端负责保真和减少确定的重复。** 重复事件包装、同一作业相同状态的轮询，可以折叠，并保留次数、时间范围及来源。不同位置出现的相同报错可能代表重复失败，不能仅凭字符串相同删除。对“仍在排查，不过已经排除了 X”这类自由文本，也不能当作普通进度直接过滤。

对于证据，优先复用已有执行记录中的小范围信息，例如执行对象、版本、结果、测试范围和产物引用。扩展这部分需要明确适配器白名单与授权范围；没有直接结果时，就保持来源归属，不把助手陈述升级成独立验证。

**整理端每批直接产出可用经验。** 模型接收新增材料、相关当前条目及必要的未解决问题，同一次处理完成正文、标题、检索摘要和语义隐私检查。发现具体证据缺口时再补读相关片段，补读计入成本。

经验的粒度建议是“一个可复用的问题或方法”。一场长任务可能产生多个条目，同一问题也可能被后续任务补充。正文应说明适用条件、实际观察、关键尝试、结果和局限；材料缺失时如实说明，不要求为了填满字段而猜测。

失败本身也可以形成有效经验，例如“这个方法在这些条件下未奏效”。不需要为了让经验获得成功标签，额外重跑业务任务，也不应从单次失败擅自推导根因。

**更新端只修改受到新证据影响的条目。** 新材料推翻旧判断时，要明确更正原结论，并在当前正文保留理解教训所必需的失败过程。环境不同的两个结果可以同时成立，不能只因为语义相似就合并；发布时间较新，也不必然意味着更有依据。

继续遵守“只保留当前有效正文”的约束。当前正文可以叙述“先误判 A，后来证据支持 B”，这不需要另建一套正文修订档案。仅保留必要的去重、处理和发送回执；原始来源不可访问时，明确说明证据缺失。该边界与现有 存储约束 (line 107) 一致。

**消费端继续提供参考知识。** 先返回问题、适用条件和摘要，再按需展开正文及来源。历史建议不能成为新的系统指令，命中经验也不强制执行其中的命令。是否复用，仍由当前任务依据现场情况判断。这与 设计原则中的知识参考性和按需介入 (line 13) 保持一致。

**成本控制应落到累计处理量，不能只统计模型调用次数。**

可以按下面的口径记账：

所有调用包括补读、重试和额外审阅。另行记录耗时、CPU、内存及存储；没有获得 token 用量时记为未知。

一个纯计算示例：假设有 100 批材料，每批新增 2,000 token，并且每批都做一次整理。

| 输入方式 | 累计输入量，不含指令和输出 |
| --- | --: |
| 每次发送累计全文 | 1,010 万 token |
| 每批新增材料＋3,000 token 相关上下文 | 50 万 token |
| 任务结束后全文只处理一次 | 20 万 token |

这说明增量方案能消除反复读取全文的浪费，**但并不证明它比任务结束后只读一遍更便宜**。后者也必须作为基线比较。

因此，建议按需求选择：材料能装入上下文、只需结束时贡献的任务，整篇一次直接提炼即可；超长任务或需要持续贡献时，采用增量更新。分批解决输入规模，局部更新减少重复加工，两者不必附带一次最终全量重写。

此外，相关旧经验也必须控制范围，否则“新增材料＋越来越大的全部经验”最终仍会重复全量处理。达到预算却没有完成必要整理时，应报告未完成范围，保留已有有效结果，不能把摘录当成完成产物。

**质量验收需要专门针对我们的技术经验，不能直接采用记忆产品的排行榜结论。**

LongMemEval 覆盖信息提取、跨会话推理、时间推理、知识更新和拒答，适合借鉴其纠正与缺失信息测试；它主要评估历史问答，不能直接证明 NPU 调试经验能帮助下一次任务。[arXiv](https://arxiv.org/abs/2410.10813)

建议用已获准的脱敏样本与合成样本，比较四条路径：现有方案、全文一次直接提炼、全部新增材料的增量提炼、候选与证据选择性提炼。固定模型和输出目标，并预留未参与提示词调整的样本。人工标注关键事实，全文模型输出仅作为对照，不作为标准答案。

| 验证情形 | 主要观察指标 |
| --- | --- |
| 相同事实加入大量等待和进度文本 | 关键经验覆盖率、累计输入量、每条有效经验成本 |
| 关键纠正埋在中间，结尾只有状态通知 | 纠正是否保留、过时结论是否仍在正文中 |
| 只有局部测试通过、工具失败或最终结果未知 | 是否错误扩张验证范围、虚构成功或根因 |
| 同一问题换版本、硬件、拓扑或参数 | 适用条件是否保留，是否错误合并 |
| 下一任务使用这些经验 | 成功情况、调查步骤、耗时、返工及读写总成本 |

噪声测试还要区分两种情况：确定重复的机器事件，应当主要由脚本消除；不同措辞的自由文本仍可能需要语义阅读，不能预先承诺模型开销不增长。

经验抽取率、引用存在率、模型自评都只能覆盖部分质量。最终还要看独立后续任务是否少走弯路，并把整理费用计算进去。

**建议的实施顺序是先建立可测基线，再做输入筛选优化。**

第一步，在现有采集路径上补齐来源标识、实际 token 记账和评测样本，先验证整理模型调用链可用。此前记录中的调用失败只说明当时没有完成验收，本轮没有重新测试其可用性。

第二步，在 knowledge 中实现真正的经验正文整理与局部更新；mindie-agent-codex 负责公开材料投影和模型适配。复用现有队列、授权检查、存储及导出路径，分别记录采集完成和语义整理完成，失败不能导致材料被当作已经处理。

第三步，再用相同样本验证候选筛选、上下文选择以及必要时的模型升级策略。只有测出质量与成本收益，才扩大默认使用范围；检索后自动重写、多轮模型评审和知识图谱都可以留作有明确需求时的候选。

**优先实现的能力应当是：每一批新材料能变成带条件、带来源、保留失败教训的经验，并且我们能准确回答“处理了哪些材料、漏了什么、花了多少、下一次是否有用”。** 这一能力成立后，再优化筛选比例和模型费用，才能避免继续在摘要形式上迭代，却没有解决经验质量问题。
