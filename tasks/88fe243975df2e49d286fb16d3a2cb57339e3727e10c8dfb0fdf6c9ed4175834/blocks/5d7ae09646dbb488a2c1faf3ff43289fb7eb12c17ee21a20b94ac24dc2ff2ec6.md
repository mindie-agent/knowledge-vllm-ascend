**四种方案的公平对照**

| 方案 | 固定做法 | 要反证的主要风险 |
|---|---|---|
| 全文一次小模型摘要 | 同一已脱敏快照，只调用一次，超上下文如实记失败 | 长输入仍可能遗漏，且完整输入不保证质量；它只是参考对照，不是默认路线 |
| 首尾小模型摘要 | 复用当前 12 KiB、前 1/3 后 2/3 的实现 | 中段唯一发现、撤回及失败被系统性丢失 |
| 结构化抽样＋小模型 | 相同总输入额度；完整消息边界，开头/结尾、均匀中段、用户修正/报错/验证结果候选各占固定份额；重叠去重，恢复时间顺序 | 关键词启发式误判、技术噪声挤掉关键上下文；“没有触发词”的修正被漏掉 |
| 小模型增量摘要 | 固定新增区段＋固定上限旧摘要；各区段只处理一次，记录摘要覆盖至何处；同样限制最终摘要长度 | 早期错误持续传播、后续摘要遗忘旧限制；多次调用固定开销可能抵消输入节省 |

公平性需要两个视角：

- **同一最终正文、同一模型版本/推理配置/输出额度**，比较最终质量和实际累计成本。全文一次不能与“全文每轮重跑”混为一谈。
- **同一整任务总预算**，比较预算内能覆盖多少新增内容。增量方案必须累计全部调用与旧摘要重送；预算耗尽记未覆盖，不能悄悄改成全文或强模型补救。

首尾与结构化抽样采用相同输入额度。增量输入大致是 `新增全文 + 调用次数 × 有界旧摘要 + 固定提示`，可能接近线性，但不是天然廉价；完整正文扫描、哈希、索引仍另算。调用用户侧 Luna 等模型也不自动等于离线推理。

**最小评测集与建议门槛**

先复用现有 10 类[合成样本](<redacted:local-path:af8f786d60f1>)，补充不同位置、长度及自然改写：

- 场景包括中段发现、先错后改、仍失败、仅局部验证、多主题、用户纠正助手、晚期撤回、中文/代码混合、敏感占位符、纯进度噪声。
- 每份 fixture 保存公开事件及时间顺序、预期可保留事实、明确不允许的推断、纠错关系、查询及相关条目 ID。加入只有工具输出含结论的对照，验收应承认公开正文没有该证据。
- 使用确定性断言检查格式、术语、哨兵、遗漏区间；人工盲评语义与纠错，不强制增加 LLM 裁判。
- 初轮建议 24–40 个固定样本、每种策略重复 2 次，另留少量未参与调参的改写版本。**这些是待校准的实验规模，不是用户要求或产品门槛。**

可先采用以下**待校准候选门槛**：在专门的纠错哨兵中，错误归属/假成功/撤回反转为 0；主题与关键条件覆盖率 ≥80%；实际 <redacted:username-at-host:8af2a1e50a32> 相对全文一次对照下降不超过 5 个百分点，同时累计模型用量至少下降 50%。需同时报告绝对分数、分场景结果和失败样本；全文对照本身失败不能成为低标准。小样本零失败也不能宣称生产零风险。

尤其不要只统计关键词：摘要含 `QueueScopeMismatch`，但把“尚未解决”写成“已解决”，应判为严重语义失败。

**最小迭代顺序**

1. **先补评测与合同一致性。** 当前 `docs/mindie-loop.md` 仍写全文模型输入，与新 `public-transcript-capture.md` 的首尾实现不一致；统一“设计目标、当前实现、未验证项”。不改运行环境。
2. **保留当前正文采集，测四种摘要策略。** 先完成离线输入覆盖和成本计数，再跑真正小模型。只替换一个内部选择/摘要策略，不新增公共 CLI、中心服务或经验评分体系。
3. **根据失败类型选择最便宜的改动。** 若正文检索命中好、主要问题是候选卡无法分辨，优先改善摘要；若中段词仍可检索且选读无损，不必为摘要完整性建设复杂流水线。只有结构化抽样仍明显遗漏时，再推进增量摘要。
4. **对胜出方案做一条原生链路。** 获准合成任务 → 摘要 → GitHub → Grok → 独立客户端，并验证一次后续修正。不重新全量验收无关能力。
5. **达到“可用且便宜”就停止扩展。** 不默认强模型蒸馏、不逐条技术认证、不建永久事实账本、不强制任务收尾报告。Grok 普通合并与可选内容维护保持分离。

可反证条件很明确：若结构化抽样不能改善中段案例，删除它；若增量摘要在纠错上更差或累计成本更高，不采用；若完整正文带来的 Git/本地成本超过收益，再单独评估保存策略，不能凭“模型输入已限额”宣称采集存储已经轻量。
