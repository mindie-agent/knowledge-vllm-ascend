原因是 `BaseMultiModalProcessor._apply_hf_processor_mm_only` 会根据子类是否 override `_call_hf_processor` 选择路径。K3 当前没有 override，于是调用 generic `call_hf_processor_mm_only`；后者只处理 `images/videos/audio`，不支持 `vision_chunks`，也不会调用 [KimiK3Processor](<redacted:local-path:22fb28f07509>:37)。

最小修复是在 [KimiK3MultiModalProcessor](<redacted:local-path:8652d4720dea>:142) 增加与 Kimi K2.5 相同的 override：

```python
def _call_hf_processor(
    self,
    prompt: str,
    mm_data: Mapping[str, object],
    mm_kwargs: Mapping[str, object],
    tok_kwargs: Mapping[str, object],
) -> BatchFeature:
    # Force cached vision_chunk misses through the joint text/MM path.
    return super()._call_hf_processor(prompt, mm_data, mm_kwargs, tok_kwargs)
```
