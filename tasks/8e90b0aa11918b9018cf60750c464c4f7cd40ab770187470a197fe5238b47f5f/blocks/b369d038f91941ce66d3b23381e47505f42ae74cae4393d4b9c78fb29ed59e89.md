3. KDA 的正面根因

KDA 使用独立的 `q_proj/k_proj/v_proj/b_proj/f_b_proj/g_proj`，均不命中 FlashComm1 column 白名单；`f_a_proj` 还是 `ReplicatedLinear`。因此不能简单扩展 prefix 白名单，否则会重复多次 all-gather，而且仍无法正确覆盖 replicated gate 路径。

当前 KDA forward：[kimi_kda.py](<redacted:local-path:238187c75437>:150)。

开启 FlashComm1 后，text-only 模型传给 KDA 的是 `[T/TP,H]` token shard，但 KDA metadata/cu_seqlens 描述的是完整 T。AscendC binding 又强制 `cu_seqlens[-1] == T`，所以会产生 shape/状态语义错误，prefill 通常直接报参数错误，decode 也会错误更新状态。

正确方案是在 KDA 所有 hidden-dependent projection 之前只做一次 token all-gather，然后再计算 `num_tokens`；保留现有 `o_proj` 的 SequenceRow reduce-scatter。

4. 多模态首层是必修路径

上游 `KimiLinearConfig.is_kda_layer` 使用 1-based checkpoint 编号：

```python
(layer_idx + 1) in linear_attn_config["kda_layers"]
```

因此 checkpoint 的 `[1,2,3,5,...]` 实际代表 0-based KDA 层 `[0,1,2,4,...]`。真实 K3 和减层模型的 layer0 都是 KDA。

对于 `KimiK3ForConditionalGeneration`，model runner 在 forward context 外生成 full `inputs_embeds`，所以首层输入是 `[Tpad,H]`，未经过 FlashComm reduce-scatter。KDA 必须静态识别：

```text
is_vl_first_layer = is_vl_model(vllm_config) and layer_idx == 0
```

并满足：

- VL 首层：跳过 KDA 输入 all-gather。
- text-only 首层及所有后续层：执行一次 all-gather。
- 首层 `o_proj` reduce-scatter 后，decoder 输出 buffer 必须是 `[Tpad/TP,H]`。
- `block_residual`（形状 `[Tpad, block_count, H]`）以及非空 `prefix_sum` 必须按同一 TP rank 在 token 维切分，否则 [kimi_k3_text.py:460](<redacted:local-path:e5785d9d5d24>:460) 会因 full/shard token 维不同而失败。

不能直接复用当前 `maybe_chunk_residual` 的 fake implementation 处理 3D `block_residual`，因为它返回 `empty_like(x)`，会丢失 residual 的额外维度。这里应静态按 TP rank 切 token 维，或同步修正该 custom op 的 fake contract。

1. `is_vl_model()` 不能单独判断首层是否为全局布局

`--language-model-only` 下模型架构仍被识别为 VL，但 runner 实际传 `input_ids`，embedding 会在 forward context 内执行 FlashComm reduce-scatter。当前代码会错误跳过首层 KDA gather。

Kimi 的最小静态判定可使用：

```python
mm_config = vllm_config.model_config.multimodal_config
has_global_first_layer_input = (
    is_vl_model(vllm_config)
    and mm_config is not None
    and (
        mm_config.enable_mm_embeds
        or mm_config.get_limit_per_prompt("vision_chunk") > 0
    )
)
```

该条件与 K3 在 vLLM 0.23.0 中的 `supports_mm_inputs` 语义一致，覆盖：

- 完整 VL 服务的纯文本请求
- 图片请求
- `--language-model-only`
- 显式 `vision_chunk=0`
- 预计算 multimodal embeddings

decoder 与 KDA 必须共用完全相同的判定。

2. 首层本地输出行数必须使用 floor

当前：

```python
(hidden_states.shape[0] + tp_size - 1) // tp_size
```

应改为：

```python
hidden_states.shape[0] // tp_size
```

原因是 SP runner 在进入 forward context 前已保证全局 token 数为 TP 的整数倍；同时现有 MLA 和 `matmul_and_reduce` fake 实现均使用 `N // TP`。`@support_torch_compile` 会将 token 维设为动态维，ceil 与 fake op 的 floor 是不同的符号表达式，可能在 Dynamo/FakeTensor 阶段造成赋值 shape guard 或 FULL_DECODE_ONLY 编译失败。

建议同步把 decoder UT 的非真实 `N=5, TP=2` 改成已 padding 的 `N=6, TP=2`。

- 后续 KDA 层在 projections 前只 gather 一次是正确的。
- 首个 VL KDA 层跳过 gather、由 `o_proj` reduce-scatter 转成 local layout 是正确的。
- `block_residual.squeeze(1) -> maybe_chunk_residual -> unsqueeze(1)` 符合该 custom op 的二维 fake/runtime 契约。
- prefill、decode、FULL_DECODE_ONLY 下的 metadata 与 KDA core 都应保持全局 token 布局。
