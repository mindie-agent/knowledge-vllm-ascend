5. KDA padding 的影响  
   Thread `PRRT_kwDONxQEAc6U95BJ`  
   [r3679518260](https://github.com/vllm-project/vllm-ascend/pull/12950#discussion_r3679518260)

   这是 ACLGraph padding 场景的正确性/精度保护，不改变 acceptable length 或 accepted-token 计算。`recurrent_kda` 跳过零长度 dummy row 后不会写对应静态输出槽；这里只清除 `query_start_loc[-1]` 后的未写尾部，防止旧值/NaN 进入 residual 和 MoE。

   可回复：

   > This is a correctness guard for graph-padded batches, not an acceptance-length change. `recurrent_kda` skips zero-length dummy sequences and therefore leaves their static output slots unwritten. We zero only the tail after `query_start_loc[-1]` before it reaches the residual and MoE layers. Real-token outputs and `num_accepted_tokens` are unchanged; UT covers both a fully populated no-op case and dummy-tail sanitization.
