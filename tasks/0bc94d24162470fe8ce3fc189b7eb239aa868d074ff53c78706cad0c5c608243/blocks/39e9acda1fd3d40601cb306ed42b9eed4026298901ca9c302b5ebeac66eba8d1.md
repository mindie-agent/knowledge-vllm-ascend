`speculative_config.max_model_len` 应省略。

vLLM 0.27.1 在该字段为空时会计算：

```python
min(draft_max_model_len, target_max_model_len)
```

Draft 配置的 `max_position_embeddings=1048576`，所以它不会限制目标模型的 1M 能力。

性能测试 8K～128K 时，仍可在服务顶层设置：

这只是本轮运行容量，不应写入 speculative config。153 上现有启动脚本的这部分设置是正确的。

3. 它是 MLA DSpark，不是 GQA

证据很明确：

- README：`Three full-causal MLA layers`
- `q_lora_rank=1536`
- `kv_lora_rank=512`
- `qk_nope_head_dim=128`
- `qk_rope_head_dim=64`
- `v_head_dim=128`
- `num_attention_heads=num_key_value_heads=96`

  - `q_b_proj=(18432,1536)`，即 `96 × 192`

  - `o_proj=(7168,12288)`，即 `7168 × (96×128)`

虽然 `num_key_value_heads=96`，但这仍然是带低秩 KV latent projection 的 MLA，不能按 GQA 判断。

4. 当前代码确实需要三处适配

第一处是 vLLM 0.27.1 配置解析。

干净版本第一次启动在加载权重之前失败：

```text
ValueError: The hidden size (7168) is not a multiple of
the number of attention heads (96).
```

根因是 `K3DSparkConfig` 继承 `DeepseekV2Config`，触发了 Transformers 的普通 MHA divisibility 校验。但该模型有显式 MLA `head_dim`，7168 不需要被 96 整除。权重 shape 也证明 96 是正确值，不能通过修改 checkpoint 的 head 数来绕过。

153 的 vLLM 源码现在已有临时 `DeepseekV2Config.__init__.__wrapped__` 绕过，但这不是干净的 0.27.1 基线，也不是理想的正式实现。最终应在 vLLM 上游让 `K3DSparkConfig` 使用适合 Kimi MLA 的配置基类或正式支持显式 `head_dim`，避免依赖 decorator 的 `__wrapped__` 内部实现。

第二处是 full-causal draft 语义。

新权重同时包含：

```json
"full_attention_causal": true,
"dflash_config": {"causal": true}
```

它需要同时控制：

- `non_causal_multi_token_decode=False`
- `get_draft_attn_causal()` 返回三层 `True`

解析顺序应为：

1. 优先使用 `dflash_config.causal`
2. 回退 `full_attention_causal`
3. 老 checkpoint 默认 `False`

当前共享工作树的未提交修改已经按这个方式覆盖。

第三处是 QuaRot 配置传递。

`72f4a62d2` 中 proposer 显式设置：

```python
quant_config=None
```

这会导致 MLA DSpark modeling 的 `get_rotation_path(vllm_config)` 得到 `None`，进而跳过：

- `context_proj` 的旋转处理
- 旋转后的 target embedding/lm_head 加载

这里应保留 target 的 quant metadata。Draft 是否量化由 `get_draft_quant_config()` 根据 draft 自己的 model/load config 单独解析，因此保留 target metadata 不会把 bf16 draft 错误地按 W4A8 加载。当前共享工作树也已经删除了这个 `quant_config=None`。

5. KV 分组和 metadata builder 不需要为 Block5 再修改

该模型有 3 个 draft MLA 层。当前分组逻辑也适用于 MLA，因为 `MLAAttentionSpec` 是 `FullAttentionSpec` 的子类。

预计布局：

- 24 个 target full-attention 层 + 3 个 draft MLA 层：一个混合 attention scheduler group
- 69 个 Mamba 层：平衡拆成 `23+23+23`
- 合计 4 个 scheduler groups

Metadata builder 预计仍是 5 次：

- target NoPE MLA builder：1
- draft RoPE MLA builder：1
- 三个 Mamba group：3

因此无需修改 KV 分组或 metadata builder。Block5 从原有 draft 层数切换成 3 层后，现有逻辑仍能泛化。
