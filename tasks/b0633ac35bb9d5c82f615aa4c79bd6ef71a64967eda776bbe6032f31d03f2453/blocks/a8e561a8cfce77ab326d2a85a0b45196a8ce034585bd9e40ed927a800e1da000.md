### assistant:commentary
我先按当前 K3 数据流核一下这两个 `routed_expert_down_proj/up_proj` 的输入输出契约和 vLLM linear 的通信语义。关键不只是把 `ReplicatedLinear` 换成 TP linear：down 后的 latent 是所有 EP rank 的专家输入，up 前又带 RMSNorm，因此切分点会决定是否额外引入 all-gather/all-reduce，以及是否和刚修的 AllGather 归约语义冲突。

### assistant:final_answer
可以切，但不能只把两个 `ReplicatedLinear` 替换掉，必须同时处理通信语义。

| 投影 | 推荐 TP 方式 | 原因 |
|---|---|---|
| `routed_expert_down_proj`：7168→3584 | `ColumnParallelLinear(gather_output=True)` | 每个 EP rank 的本地专家仍需要完整 3584 latent，因此切完输出必须 all-gather |
| `routed_expert_up_proj`：3584→7168 | `RowParallelLinear(input_is_parallel=False, reduce_results=True)` | 输入按 TP 切分计算，输出通过 all-reduce 恢复完整 hidden state |

这两个维度在 TP8、TP16 下都可整除。

需要注意：

- K3 在 up-proj 前有 RMSNorm，所以 AllGather 必须先归约完整的 3584 latent，再执行 `RMSNorm → RowParallel up-proj`。
- up-proj 应先用 `reduce_results=True`。如果设成 `False`，输出还是 TP partial，而当前 runner 会认为 routed output 已归约并跳过最终 all-reduce，结果会再次错误。
- down-proj 使用 `gather_output=True` 会增加一次 TP all-gather；否则 fused MoE 的本地专家拿到的只有 3584/TP 个通道，现有专家权重无法计算。
- up-proj 会增加一次 TP all-reduce。AllGather 场景因此需要：
  1. routed latent all-reduce，保证 RMSNorm 正确；
  2. RowParallel up-proj all-reduce，合并线性层 partial。
- 权重和计算量可以降到约 `1/TP`，但 decode 小 batch 下新增 collective 可能抵消收益，需要实际测吞吐。

所以结论是：可以切，最稳妥的第一版是 `ColumnParallel(gather_output=True) + RowParallel(reduce_results=True)`。当前 PR 的归约修复与这个方案兼容，但要补 TP-sharded projection 的权重加载、数值和性能验证。Gate/router logits 那个 `ReplicatedLinear` 则不建议一起切，因为全局 top-k 仍需要完整 896 expert logits。

### assistant:final_answer
对，按当前 EP/FusedMoE 的实现，不能完全复用普通 MLP 的“ColumnParallel 保持分片，直到 RowParallel 才 all-reduce”模式。

普通 MLP 可以这样做：

```text
ColumnParallel（输出分片）
→ SiLU 等逐通道算子
→ RowParallel
→ all-reduce
```

因为中间激活是逐通道的，后一个 RowParallel 可以直接消费对应分片。

K3 routed projection 当前需要：

```text
ColumnParallel down-proj
→ TP all-gather，恢复完整 3584 latent
→ routed MoE
→ 合并所有 expert-rank 的 routed partial
→ RMSNorm
→ RowParallel up-proj
→ TP all-reduce
```

原因有两个：

1. 当前 EP expert 权重没有沿 latent hidden dimension 做 TP 切分，本地专家需要完整的 3584 输入。
2. up-proj 前的 RMSNorm 依赖全部 3584 个通道，不能直接对各 TP feature shard 独立计算。

AllGatherEP 下实际有三类归并：

1. down-proj 后 feature shard 的 TP all-gather；
2. MoE 后 expert partial 的 all-reduce，必须发生在 RMSNorm 前；
3. RowParallel up-proj 的 TP all-reduce。

AllToAll/MC2 会在 combine 内完成第 2 步，因此显式增加的主要是 down-proj all-gather 和 up-proj all-reduce。

若想像普通 TP MLP 一样只在最后 all-reduce，就必须进一步把 expert GMM 权重也沿 latent 维切分，并实现分布式 RMSNorm，相当于改成 TP×EP 二维并行，改动会明显更大。
