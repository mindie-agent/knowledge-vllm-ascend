R10 的 ring 实验不能否定这一点：它仍是旧 packed/interleaved 全套改动，且卡在后续 decode，dump 中 `new_block_ids_to_zero=null`；R14 则是在首批新 block 清零时卡住，是另一条路径。

所以这次不只补一个 ring。我会把 zeroer 整体改成上游模型：**按 page size 分组、每组使用静态 page-size kernel、按 `max_concurrent_batches` 轮转 H2D 源和目标 buffer**，然后基于同一 global `[K][V]` 方案重拉。这个 A/B 如果通过，就能完整解释“为什么改前只错精度、改后会卡死”；如果仍卡，剩下唯一主嫌就是 promoted parent→kernel block 的地址映射本身。
