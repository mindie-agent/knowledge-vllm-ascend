结论：这是上游依赖不匹配，不是 ViT 计算问题。

PR 注入了 `{"image": {"image_mode": None}}`，但 vLLM v0.26 的 `MediaConnector` 仍以显式参数加 `**kwargs` 构造 `ImageMediaIO`，因此重复传参。该能力直到上游提交 `15cb8e140` 才完整实现；只改构造方式也不够，因为旧版 `ImageMediaIO` 不支持以 `None` 保留原始模式。

建议在现有 renderer UT 中加入真实连接器回归：

```python
from PIL import Image
from vllm.multimodal.media import MediaConnector
from vllm.multimodal.utils import encode_image_url


def test_k3_media_defaults_work_with_vllm_connector():
    image_url = encode_image_url(Image.new("RGB", (1, 1)))
    connector = MediaConnector(
        media_io_kwargs=renderer_patch._merge_k3_media_io_kwargs(None)
    )

    image_sync = connector.fetch_image(image_url)
    image_async = asyncio.run(connector.fetch_image_async(image_url))

    assert image_sync.size == (1, 1)
    assert image_async.size == (1, 1)
```

当前 v0.26 会精准复现 `multiple values for keyword argument 'image_mode'`。修复应集中在 K3 media kwargs 默认层，同时覆盖同步、异步 renderer；现有两个把 `image_mode=None` 固化为预期值的 mock 断言也需同步修改。
