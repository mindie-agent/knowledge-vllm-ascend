### assistant:final_answer
如果你指 vLLM 在 GPT-OSS 首发时用的 CUDA attention sink 快路径，来源是：

**Dao-AILab FlashAttention 3 → vLLM 的 flash-attention fork → 增加 `s_aux` 支持。**

具体链路：

1. GPT-OSS 的 sink 数学语义来自 OpenAI 官方参考实现：把每个 head 的可学习参数 `S` 作为额外 logit 拼到 `QK` 后做 softmax，随后丢掉 sink 对应的概率。因此它相当于一个“只有 logit、value 为 0 的虚拟 token”。[OpenAI 参考实现](https://github.com/openai/gpt-oss/blob/main/gpt_oss/torch/model.py#L153-L173)

2. FlashAttention 3 的优化实现是在 `vllm-project/flash-attention` fork 里加的，不是当时 Dao-AILab 主仓原生已有的 GPT-OSS 专用算子：

   - [vllm-project/flash-attention PR #75](https://github.com/vllm-project/flash-attention/pull/75)
   - 合入 commit：`b99f8c8217`
   - 主要改动是给 SM90/FA3 kernel 加 `S aux`。

3. vLLM 通过 [PR #22313](https://github.com/vllm-project/vllm/pull/22313) 把 flash-attention 依赖升级到这个 commit，然后在 [PR #22320](https://github.com/vllm-project/vllm/commit/6e20924350e3fed375bc63d55166a303b6f0828a) 里把模型的 `sinks` 接到 FA3 的 `s_aux` 参数。

另外，vLLM 还有一套自己的 Triton 实现：

- 基础 `triton_unified_attention` 来自 [PR #16828](https://github.com/vllm-project/vllm/pull/16828)，主要作者是 IBM 的 Thomas Parnell 等。
- sink 支持同样由 #22320 加进去。它没有真的拼接一个 token，而是把 online-softmax 初值设为：

```text
M = sink
L = 1
acc = 0
```

这与 OpenAI 参考实现的 `cat([QK, S]) -> softmax -> 去掉最后一列` 数学等价。

所以一句话总结：

> **语义来自 OpenAI GPT-OSS；Hopper 上的优化算子来自 vLLM 的 FlashAttention 3 fork；Ampere/Triton 路径则是 vLLM 自己的 unified-attention kernel 后加 sink 支持。**

如果你问的是 Ascend 当前代码里的那个，则又不同：它走的是 CANN/torch-npu 的 `npu_fused_infer_attention_score_v2(..., learnable_sink=...)`，vLLM-Ascend 只是通过 [PR #5901](https://github.com/vllm-project/vllm-ascend/pull/5901) 接入，并不是移植上述 CUDA kernel。[torch-npu 接口文档](https://www.hiascend.[REDACTED_SECRET].md)
