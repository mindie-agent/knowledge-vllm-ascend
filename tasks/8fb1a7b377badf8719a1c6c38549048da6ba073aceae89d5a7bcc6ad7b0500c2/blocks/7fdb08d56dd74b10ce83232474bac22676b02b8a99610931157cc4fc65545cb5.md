### assistant:final_answer
最小设计可以冻结为：**正文和发布资格不因引用关系改变；只在检索层用确定性来源关系减少重复结果，直接读命中的块。** 不增加模型分类、可信度等级、发布审批或通用知识图谱。

建议锁定以下约束：

- `cites` 是块级派生信息，只来自规范引用或可信工具回执，含义仅为“引用了”，不表示原创、验证或独立证据。无需写进正文。
- 同一可解析来源链，只有来源正文也匹配当前查询时才归组。匹配不能来自拼接的摘要/导航；可要求来源正文匹配的 query token 覆盖衍生块的匹配 token，避免一个公共词就吞掉新观察。
- 原文是组的来源锚点；组内修正、反例、失败记录仍按查询相关性显示自己的 excerpt 和可读 block ref。禁止只返回原文加 `related_count`。
- `limit` 按组计，相关命中可分页。精确 task/block ref 查找不能被归组改成另一个目标。
- 多源、环、缺失、跨域不强行推导“共同根”，保持普通结果和引用提示。格式合法但目标退役可以 unavailable；磁盘读取、校验失败必须报错。
- block ref 绑定 `block_id + 文件 hash`，读取时必须仍是当前 manifest 的成员；task 追加不使已有 block ref 失效。合法替换/撤回是 superseded/unavailable，文件损坏是 error。

任务包与 Bot 维护应共用一套机械包操作：

1. 改标题、摘要或导航，只改 manifest 并重算绑定。
2. 修正文，生成新 block ID、替换 manifest 引用并删掉旧当前文件；不能同 ID 改不可变正文。
3. 撤回整任务，删除整个包；普通检索退出，旧引用解释为已不可用。
4. 生产者后续续接，以已确认的远端包为基线，只追加本地未发送的新块，保留 Bot 修改；未知写入先核对。
5. 原始来源撤回，不自动删除引用它的独立反例/新验证；只有纯引用关系变为不可用。

当前 `community/publish.py:_prepare_files` 对远端变动明确 conflict 是正确保护；但不能停在“Bot 一修索引，后续生产者永远冲突”。同一 helper 应覆盖 hash/revision/topology，Bot 不手算。

建议纯合成验收，使用虚构 NPU/算子场景，不读私人材料、不调用模型：

| 场景 | 必须证明 |
|---|---|
| A 原始 RMSNorm 记录，B/C 仅复述 A | 一个检索组；A 可直接读；B/C 可展开；不伪称三份独立证据 |
| D 引用 A，新增 BF16 非连续输入失败 | 独有关键词查询直接命中 D；正文完整保留 |
| D 与 A 使用同一关键词，但结论相反 | 可归组，但 D 的失败 excerpt/ref 仍直接可见 |
| A 只有摘要含查询词，正文不含 | 不因摘要把 B 折叠到 A |
| 同域多来源、循环、已撤回源、跨域源 | 不误归组、不删除后续经验、无无限遍历 |
| 命中长任务中间块后读 ref | 只读对应块；不拼接整任务；追加后旧块引用仍有效 |
| Bot 改一个块，生产者随后追加新块 | Bot 改动保留；旧块不复活；当前包通过同一 validator |
| Bot 整包撤回，生产者仍有待发增量 | 不自动复活同 task；引用该任务的独立反例仍存在 |
| ref hash 过期与文件损坏 | 前者明确 unavailable，后者明确 corruption error |
| adapter/runtime/validator schema 不一致 | 切换前拒绝整套组合；不能更新一半后才发现 |

还有一个需要明说的范围问题：已重打包的 20 条公开案例保留了旧 `mindie://<redacted:username-at-host:d6f1d3185647>` 引用。若它们已经失效，严格解析只会标记 missing，现有回声不会自动消失。应选择一次性、可证明的迁移对应关系或明确维护当前样本；不需要建立长期兼容层，但不能只测新引用就宣称旧回声已解决。
