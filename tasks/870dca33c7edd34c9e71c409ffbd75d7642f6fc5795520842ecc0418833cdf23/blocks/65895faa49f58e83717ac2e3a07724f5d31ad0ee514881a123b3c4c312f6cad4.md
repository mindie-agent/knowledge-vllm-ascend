每次执行：
1. 获取上述四个远程分支的最新 SHA，并记录 new 的远端旧 SHA 以供精确 --force-with-lease 使用。
2. 验证 releases/v0.23.0 是当前 ci 的祖先、当前 ci 是当前 ci_new 的祖先；若不成立则失败，不修改任何远端分支。
3. 重新生成 new：从 releases/v0.23.0 建临时分支，将 ci_new 的最终树 squash 到工作区，再反向应用“releases/v0.23.0 到 releases/v0.23.0_ci”的完整二进制 diff，从而仅减去私仓 CI 修改。若反向应用冲突则失败，不推送错误结果。开发 diff 非空时使用 Conventional Commit 消息并带 Signed-off-by 创建一个汇总提交；为空时目标直接指向公开基线。
4. 校验 new 相对 releases/v0.23.0 的提交数只能是 0（开发修改为空）或 1（开发修改非空）；有开发修改时必须为 1，且唯一提交的父提交必须为公开基线。再做树级语义校验：从候选 new 树出发，将 releases/v0.23.0 到 releases/v0.23.0_ci 的 CI 补丁正向应用到临时索引，git write-tree 的结果必须与当前 ci_new 的 tree SHA 完全相同。不要用原始 git diff 文本或 blob index 行做严格相等校验。
5. 只有远程 new 的目标 SHA 或树/父关系需要变化时，才使用精确的 --force-with-lease 推送 releases/v0.23.0_new。
6. 任意 lease 失败说明期间出现新推送：不要覆盖，重新 fetch 并从头重算，本次最多重试一次；仍失败则报告。
7. 无变化时简短结束。绝不修改或推送 releases/v0.23.0、releases/v0.23.0_ci 或 releases/v0.23.0_ci_new。
