### assistant:final_answer
根因确认了：这次不是 HCCL，而是 QuaRot embedding 克隆逻辑。

触发链：

1. MLA DSpark checkpoint 没有自己的 `embed_tokens`。
2. target 是 QuaRot 权重，draft 不能直接复用已经旋转的 target embedding，必须创建一份 draft-owned 的反旋转权重。
3. 代码执行 `copy.deepcopy(target_layer)`。
4. `AscendVocabParallelEmbedding` 持有 `comm_group = get_tp_group()`，内部包含不可 pickle 的 `torch.distributed.ProcessGroup`。
5. `deepcopy` 递归到 ProcessGroup 后报错。

证据位于 [mla.txt](<redacted:local-path:5e6e492e9b4b>:344)、[llm_base_proposer.py](<redacted:local-path:243012d1c4c6>:339) 和 [vocab_parallel_embedding.py](<redacted:local-path:9d758bd37db8>:62)。

最小正确修法是 deepcopy 时复用通信组，只克隆模块参数：

```python
comm_group = getattr(target_layer, "comm_group", None)
memo = {id(comm_group): comm_group} if comm_group is not None else {}
draft_layer = copy.deepcopy(target_layer, memo)
```

不能直接共享 `target embed_tokens.weight`，因为 QuaRot target embedding 已旋转，会破坏 draft 对齐和采信率；也不建议临时把 target 的 ProcessGroup 置空，会修改正在使用的 target 模块。
