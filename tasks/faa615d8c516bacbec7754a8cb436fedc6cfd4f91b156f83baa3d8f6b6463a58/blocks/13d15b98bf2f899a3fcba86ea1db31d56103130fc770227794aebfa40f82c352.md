- KDA 当前的 FlashComm 布局是正确的：首个 VL decoder layer 使用 global hidden，后续层先一次性 all-gather hidden，再执行 q/k/v/b/f/g 的投影；KDA core 和 metadata 都按完整序列计算，最后 `o_proj` reduce-scatter 回 TP-local。positions 不需要分片，KDA 本身不使用它。
- learned residual 的处理也是正确方向：第一层 attention 从 global 转 local 后，需要同步切分 `block_residual`；后续 residual mixing 都是逐 token 的 local 计算。新增 shape anchor 运行时是 no-op，不改变数值。
- MLA 存在一个明确的 FlashComm 精度错误：当前代码先对 TP-local hidden 执行列并行 `g_proj`，再 all-gather gate logits。不同 TP rank 持有不同 head 的 gate 权重，因此拼接后会发生 token/head 错配。例如 rank 0 后半段 token 会错误使用 rank 1 的 gate head 权重。

正确顺序应为：

```python
gate_input = torch.ops.vllm.maybe_all_gather_and_maybe_unpad(
    hidden_states.contiguous(), need_gather_q_kv
)
gate = self.g_proj(gate_input)[0]
```

随后不要再 gather gate。

减层 5 层实际是 `KDA/KDA/KDA/MLA/KDA`，所以这个 MLA 问题会直接进入当前四种精度 case。现有 `test_kimi_k3_gate_uses_same_gather_unpad_as_q_and_kv` 固化了错误顺序，需要改成验证“先 gather hidden、再调用 g_proj”。

另外有两个低风险一致性项：

- MLA wrapper 的首层判断仍使用通用 `is_vl_model`，最好与 KDA/decoder 统一为 `uses_global_inputs_embeds`，避免禁用视觉模态或纯 text-model 加载时重复分片。
- 首层输出 buffer 当前使用 `N // TP`；runner 会把 N pad 到 TP 整数倍，因此现有路径正确，但可参考 Qwen3.5 改成 ceil division，增强防御性。
