因为 linear 和 RMSNorm 都没有切分，并且逐 token 独立计算：

\[
\operatorname{AllGather}(F(X_r))
=
F(\operatorname{AllGather}(X_r))
\]

其中 \(F\) 可以是完整权重的 linear 或 RMSNorm。RMSNorm 只在 hidden 维归约，AllGather 发生在 token 维，因此数学上等价。

当前 K3 FlashComm 修改也没有改动：

- fused MoE 的路由与 expert map
- routed/shared expert 的计算
- EP 通信后端选择

只读审计结论：当前首层 FlashComm1 布局在单节点 DP1/TP16 下是闭合的，没有看到一个明确的“eager 正确、ACLGraph replay 必然错误”的首层语义分支。

关键事实：

- runner 在进入模型前先把 token 数补到 TP 的倍数；当前 text/image/decode 对应的 on 路径分别应是：

  - 文本 prefill：299 → 304 → local 19
  - 图片 prefill：262 → 272 → local 17
  - 单请求 decode：1 → 16 → local 1

  相关逻辑在 [model_runner_v1.py](<redacted:local-path:2914e0f8fc77>:2819)。

- K3 是 VL model，所以即使纯文本请求，runner 也传全局 `inputs_embeds[:num_tokens_padded]`，不会因为没有图片而切换成局部 `input_ids` 路径，见 [model_runner_v1.py](<redacted:local-path:2914e0f8fc77>:3508)。
- 首层执行链是：

  `global [Npad,H] → attention/o_proj reduce-scatter → local [Npad/TP,H] → chunk block_residual → local learned residual`

  实现在 [kimi_k3_text.py](<redacted:local-path:25801955574d>:466)。`block_residual.squeeze(1)` 在 layer 0 是安全的，因为 layer 0 一定刚加入了唯一一个 residual block。
- 后续 KDA 在投影前用框架现有的 `maybe_all_gather_and_maybe_unpad` 恢复 global token 布局，见 [kimi_kda.py](<redacted:local-path:c0ff1f9817eb>:159)。因此没有必要再写 K3 私有的 pad/unpad。
- `RMSNorm`、replicated linear 和 learned residual 都只在 hidden/block 维计算，不跨 token；把 token 分片前后移动不会改变数学语义。

关于 pad/unpad，有一个容易误判的点：

- 当前 `set_ascend_forward_context` 收到的已经是 `num_tokens_padded`。DP1 下它必然能被 TP16 整除，所以 `_EXTRA_CTX.pad_size == 0`，见 [ascend_forward_context.py](<redacted:local-path:f94efecbb286>:141)。
- 因此 graph 的 15 个 inactive decode rows不会在 K3 内部被切掉，而是全程保留，由 `num_actual_tokens`、`slot_mapping=-1`、重复的 `query_start_loc` 和最终 logits index 屏蔽。这是框架的 graph padding 语义；如果 K3 手动把 16 解 pad 成 1，反而会破坏 graph 固定 shape。
- `maybe_all_gather_and_maybe_unpad` 的 fake/meta 只表达 `rows × TP`，没有表达 runtime 的 `[:-pad_size]`，见 [register_custom_ops.py](<redacted:local-path:762d168e199e>:108)。当前 DP1 因为 `pad_size=0`，fake 与 runtime 一致；以后扩到 DP padding 时需要重新检查，不能直接外推。

Dynamo shape anchor：

- [kimi_k3_text.py](<redacted:local-path:25801955574d>:364) 中第二次 `maybe_chunk_residual(prefix_sum, mixed)` 不是一次实际的 pad/chunk。
- 这时两者首轴相等，runtime 原样返回 `mixed`，无通信、无数值变化；fake 用 `empty_like(prefix_sum)` 重新绑定动态 token SymInt。
- 所以它首先是 torch.compile/fake-meta 风险点，不是 ACLGraph replay 数值风险点。若 eager 通过而 graph 不通过，建议在中间插入一次“torch.compile 开启、cudagraph_mode=NONE”，把 Dynamo/Inductor 与 ACLGraph 分开。

建议按以下顺序定位：

1. `enforce_eager`：

   - FlashComm off/on × 纯文本/图片，共四个 case。
   - greedy、固定输入、固定输出长度。
   - 比较完整 token IDs，同时记录每一步 top logits 和 top1-top2 margin。
   - 一旦 token 分叉，后续自回归输入已经不同；应使用同一 token prefix teacher-force 比较首个分叉点。

2. eager 若不一致，先比较这些 canonical tensor，不看 ACLGraph：

   - layer 0 input norm 后的 active rows；
   - layer 0 o_proj 后：对 FlashComm local 输出 all-gather，再与 off global active rows比较；
   - layer 0 chunk 后的 `block_residual`；
   - layer 1 KDA gather 后的 hidden；
   - 各 KDA 层 active token 的 `q/k/v/raw_gate/beta`；
   - prefill 结束和每次 decode 后的 active `conv_state/recurrent_state`。

3. eager 若一致，再测 `compile + cudagraph NONE`：

   - 这里失败说明是 dynamic shape、fake/meta 或编译图问题。
   - 这里也一致、只有 FULL_DECODE_ONLY 失败，才锁定 ACLGraph capture/replay。

4. FULL_DECODE_ONLY 下重点验证 KDA persistent metadata，而不是先改首层：

   对 capture size 16、runtime active request 1，预期：

   - `non_spec_query_start_loc == [0, 1, 1, ..., 1]`
   - 第一个 `state_index` 有效，后 15 个为 `NULL_BLOCK_ID`

   这部分已有专门的 graph padding逻辑，见 [gdn_attn_builder.py](<redacted:local-path:f3ce715cca8c>:304) 和 [gdn_attn_builder.py](<redacted:local-path:f3ce715cca8c>:758)。
