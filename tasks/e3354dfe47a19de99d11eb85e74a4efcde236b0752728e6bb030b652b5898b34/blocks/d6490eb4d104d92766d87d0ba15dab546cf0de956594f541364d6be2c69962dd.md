## 第 2 页　Agent 自己写脚本整理多卡日志

### 建议标题

**Agent 把 64 份日志对齐到同一条时间线**

### Agent 实际完成的处理

1. 给日志补齐身份

   `请求 / 卡号 / 步骤 / Layer / 数据块`

2. 自动清洗日志

   `重复记录 / 缺行 / 打印乱序 / 同一请求被拆成多段`

3. 第一轮只抽取轻量摘要

   `shape / 最小值 / 最大值 / NaN 数量 / 内容 hash`

4. 按业务位置对齐

   `同一请求 + 同一步骤 + 同一 Layer`

5. 分层比较

   `卡与卡 / Cache 首次运行与复用 / 前一步与后一步`

6. 自动输出下一轮定位信息

   `最早变化的位置 / 变化前后的结果 / 下一轮应该采哪里`

### 可以直接画成的数据漏斗

> 64 个进程的粗粒度扫描  
> → 聚焦问题所在的 16 张卡  
> → 1 份调度记录 + 16 份结构化日志  
> → 1 条请求时间线  
> → 1 个最早变化的位置

### 右侧结果卡可以写

```text
分叉之前
16 张卡结果一致，数值正常

最早异常
主模型 Layer 23 出现 448 个 NaN

继续执行
Layer 24 开始扩散

下一轮
检查最后一次写入和第一次读取
```

### 推荐口播

> 多卡日志的问题不只是数量多。不同进程打印速度不同，还会出现重复、缺行和乱序。Agent 先写脚本补齐请求、卡号、步骤和 Layer，再按同一个业务位置对齐。最后给人的不是几十份日志，而是一张差异表，以及数值第一次变化的位置。

### 一个很能体现 Agent 主动性的细节

早期采集器曾把同一个请求的三个处理片段当成三个请求。Agent 根据相同的请求 ID 发现这个问题，修改了清洗和去重逻辑。

这句话适合口播，能说明 Agent 也会检查采集数据本身是否可信。

### 低频词汇替换

| 代码里的说法 | 汇报中的说法 |
|---|---|
| rank | 卡或进程 |
| backing | 同一块物理内存 |
| nonfinite | NaN 或异常数值 |
| dummy replay | 没有有效 token 的一次回放 |
| fence | 一次完整等待 |
| collective | 多卡通信 |
| HardEvent | 算子内部的同步标记 |

## 第 3 页　裁剪权重提高实验频率

### 建议标题

**16 专家权重把早期定位搬到单机**

### 最适合上屏的硬数据

| 维度 | 完整权重 | 16 专家调试权重 |
|---|---:|---:|
| 模型深度 | 93 层 | 93 层 |
| 每层专家数量 | 896 | 16 |
| Tensor 数据量 | 1.486 TB | 121.3 GB |
| 运行资源 | 4 机 64 卡 | 单机 8 卡 |
| 权重加载 | 历史记录约 278 秒 | 实测约 29 秒 |
| 图捕获 | 历史记录约 195 秒 | 实测约 72 秒 |

补充计算：

- 专家数量减少到原来的 `1/56`。
- Tensor 数据量约缩小 `12.3 倍`，减少约 `91.8%`。
- 单次占卡数量从 64 张降到 8 张。
- 按卡数推算，同一 64 卡资源池最多可以划出 8 个实验槽。

### 裁剪时保留了什么

- 全部 93 层
- Attention
- 共享专家
- Embedding
- LM Head
- 每个 MoE 层保留 16 个专家
- 每次仍选择 16 个专家

因此它保留了完整的层间执行路径，主要缩小的是专家权重规模。

### 已经跑通过的内容

- 调试权重已在单机 8 卡环境启动。
- 完成图模式捕获。
- 完成一次确定性的 `8192 token 输入 → 5 token 输出`请求。
- 生成并发布一份 16 专家调试权重的历史记录约为 3 分 11 秒。

### 推荐口播

> 完整权重每次都需要四机 64 卡，很多早期判断还用不到全部 896 个专家。我们保留 93 层和关键结构，只把每层专家裁到 16 个。这样功能检查、加载检查和局部数值对比可以先在单机完成，方向收窄以后再回完整权重确认。

### 耗时数据必须带的脚注

> 完整权重和裁剪权重来自不同框架与运行拓扑，耗时只用于说明历史量级，不计算加速倍数。

因此不要写：

- “启动速度提升 4.7 倍”
- “实验效率提升 8 倍”
- “可以稳定并行跑 8 组实验”

可以写：

- “单次占卡从 64 张降到 8 张”
- “按卡数最多可以划出 8 个实验槽”
- “8 路同时运行尚未单独验收”

## 开场口径

> K3 的完整权重需要四机才能拉起，但定位过程没有一直停留在四机整网上。Agent 先把现象拆成一轮轮可以验证的假设，再把多卡日志整理成同一条时间线，最后通过 16 专家权重提高实验频率。

## 三页之间的转场

第一页到第二页：

> 触发条件缩小以后，Agent 开始把多卡日志整理成可以直接比较的结果。

第二页到第三页：

> 日志已经告诉我们下一轮要采哪里，接下来的瓶颈变成四机实验的启动和资源成本。

## 结尾口径

> 人负责判断假设是否合理，Agent 负责设计下一轮实验、生成采集脚本并整理结果。每轮结束以后，留下的是一个更小的问题，以及下一步明确要验证的内容。
