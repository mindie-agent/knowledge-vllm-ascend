`Setting attention block size to 384 tokens to ensure that attention page size is >= mamba page size.`

所以“384+1”不是巧合，正是 v0.26 混合 KV/Mamba 缓存强制出来的 attention page 边界。现在根因候选已经从“大范围 Mamba 生命周期”进一步缩到：**第 385 个 token 换页时，Attention block 与 Mamba state block 的边界语义不一致，A3 的 copy/restore 路径拿错上一页状态或覆盖当前页**。这与“不带 DSpark 也坏、A5 不坏、0.23 不坏”完全一致。我正在对比 0.23 与 0.26 的 `patch_mamba_config / MambaManager / preprocess_mamba` 三段边界逻辑。

### assistant:commentary
又找到一条几乎一一对应的上游证据：vLLM 在 **v0.26.0 发布之后**已有提交 `8472b0161`，标题就是 “Cache a mamba align state block only at its own boundary”。它描述的缺陷是：跨过 block boundary 时，把“实际已计算到 385+”的 recurrent state 错挂在“只到 384”的 prefix hash 下；下一请求命中后会恢复一个超前/落后的状态。修复也正是只允许状态落点精确位于自身 block boundary 时入缓存。
