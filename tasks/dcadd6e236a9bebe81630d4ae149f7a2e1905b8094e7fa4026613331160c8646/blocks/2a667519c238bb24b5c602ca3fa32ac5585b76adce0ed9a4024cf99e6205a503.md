只读调查完成，没有修改代码/配置或启动新会话。

| 客户端 | 可用原生接入 | 限制 |
|---|---|---|
| Cursor Agents Window | `.cursor/worktrees.json` 在新 worktree 创建后、继续创建 Agent 前运行。可在新目录内完成版本选择、依赖准备、客户端配置 | `sessionStart` 异步执行，不能用于切换目录或等待更新 |
| Claude Code | `WorktreeCreate` 替代默认创建逻辑，返回绝对目录，客户端将它作为会话 cwd | 仅原生 worktree 模式触发，普通 local session 不触发 |
| Cursor IDE 普通聊天 | `sessionStart` 可关联 VAWS task | 未找到让每次普通聊天强制产生 worktree 的项目级公开契约 |

本机安装证据：

- Cursor **3.19.19**，`workbench.glass.main.js`：创建路径后 `await I9v(...)` 等待 setup，最长 300 秒；setup 失败记录状态后继续创建 Agent。因此失败应保留可用旧版本，避免半更新。
- 同 bundle 的 `sessionStart` 为无 `await` 的 async IIFE；官方也明确它是 fire-and-forget。
- 存在 **Default Environment → New Worktree** 设置（内部 `newAgentDefaultEnvironment`），可初始化时配置一次。但 UI 受 feature flag 控制，应确认实际可见，不能仅凭代码声称已经启用。
- Cursor CLI **2026.09.08-6caf4ff** 支持原生 `--worktree` 与 setup。其 `setup-worktree-unix` 实际实现按脚本路径处理；兼容接线宜用字符串脚本路径，或通用 `setup-worktree` 命令数组。
- Claude **2.1.143**，本机 help 和二进制都确认 WorktreeCreate 支持。最新版文档的若干 resume 修复要求 2.1.198/2.1.212 以后，不能直接将最新版全部语义视为此安装版已验收。

最小实现建议：

1. **Cursor** 接原生 worktree setup；**Claude** 接 WorktreeCreate。版本准备只发生于它们明确交付的“新目录”边界。
2. 继续用已有 SessionStart 关联原生 session ID 与 VAWS task；resume 只读取原有目录和环境。
3. Hook/MCP 启动器根据实际新 worktree 的环境收据选择组件，不能继续固定到初始化母仓的旧解释器。Claude `${CLAUDE_PROJECT_DIR}` 在进入 worktree 后仍可能指向母仓，必须使用事件 `cwd`。
4. 当前 Cursor 仍有 Agent 负担：setup 排除了 `PreToolUse`；coordinator 自动补 `context_file` 也只支持 Claude/Codex/Grok，提示文本因此要求 Agent 手传。Cursor 已支持 `preToolUse.updated_input`，可以仅对 VAWS MCP 调用匹配并内部补参；首个调用按原生 ID 幂等关联，解决异步 SessionStart race。
5. 普通 local session 无 native worktree 契约时应保留 local 语义，不能在每个文件工具前偷偷改路径，也不宜写另一个通用 session 状态机。

来源：[Cursor worktree setup](https://cursor.com/docs/configuration/worktrees)、[Cursor hooks](https://cursor.com/docs/hooks#sessionstart)、[Claude WorktreeCreate](https://code.claude.com/docs/en/hooks#worktreecreate)、[Claude worktree / resume](https://code.claude.com/docs/en/worktrees)、[Claude Desktop](https://code.claude.com/docs/en/desktop)。
