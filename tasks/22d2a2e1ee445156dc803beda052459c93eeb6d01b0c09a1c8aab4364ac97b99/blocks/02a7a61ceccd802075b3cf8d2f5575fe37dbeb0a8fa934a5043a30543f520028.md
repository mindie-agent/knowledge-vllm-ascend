只读审计结论：

- 这不是 DSpark 算法缺陷，而是 K3 多模态外层 wrapper 的既有接口缺口，被 DSpark 首次触发。
- vLLM v0.23.0 和当前 `origin/main` 都对最外层 `self.get_model()` 执行 `supports_eagle3(...)`，不会自动 unwrap `language_model`。
- Qwen3VL、Qwen2.5VL、Gemma4、Mistral3、Llava、KimiK2.5、Pixtral 等主线多模态 wrapper 都在 outer class 暴露 `SupportsEagle3`；ci-new 和 K3 main feature 分支的 `[REDACTED_SECRET]` 都没有。
- 代码库没有独立 `SupportsAuxHiddenStates` 接口；实际契约是 `SupportsEagle3`、`set_aux_hidden_state_layers()`，以及 `forward()` 透传 `(hidden_states, aux_hidden_states)`。
- DSpark 将 `use_aux_hidden_state_outputs=True`，因此才进入这项严格检查。普通 K3 推理不请求中间层输出，所以缺口此前一直未暴露。

最小临时修复应放在 K3 outer wrapper：

1. 继承 `SupportsEagle3`。
2. 显式将 `set_aux_hidden_state_layers()` 和 `get_eagle3_default_aux_hidden_state_layers()` 转发给 `language_model`。
3. outer `forward()` 保持直接返回 inner 输出，并放宽 tuple 返回类型。
4. 加 outer `supports_eagle3()` 与转发回归测试。

当前共享树中的未提交实现正是这套方案，方向正确。不能只加 `SupportsEagle3`：协议默认 setter 要求 `inner.model` 是 `EagleModelMixin`，而 K3 使用自定义 attention-residual capture，不继承该 mixin，因此必须显式 delegate。

不建议修改 runner 做 unwrap：这会扩大公共 runner 行为、偏离主线 wrapper 约定，并可能把未承诺 tuple 输出的模型误判为支持 aux hidden states。
