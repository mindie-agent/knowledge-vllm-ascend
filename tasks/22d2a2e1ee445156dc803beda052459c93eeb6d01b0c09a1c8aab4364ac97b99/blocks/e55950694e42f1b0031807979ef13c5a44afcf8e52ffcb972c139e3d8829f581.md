1. 必须更换 `kv_port`

[launch-k3-dspark-pd-temp.sh](<<redacted:local-path:b8dd889167fe>/launch-k3-dspark-pd-temp.sh:19>) 当前 P=`24000`、D=`25000`。官方 Mooncake 指南规定 16 NPU 节点的 AscendDirectTransport 随机占用 `20000–35999`，建议 `kv_port >= 36000`。当前值存在间歇性 `Address already in use` 风险。[官方依据](https://github.com/vllm-project/vllm-ascend/blob/main/docs/source/tutorials/features/pd_disaggregation_mooncake_multi_node.md)

建议：

- Prefill：`36000`，实际 DP0/DP1 handshake 范围 `36000–36031`
- Decode：`36100`，实际范围 `36100–36131`

范围来自 connector 的 `kv_port + global_dp_rank × TP` 和每个 TP worker 的端口展开：[scheduler](<<redacted:local-path:b8dd889167fe>/vllm-ascend-kimi-k3-dspark/vllm_ascend/distributed/kv_transfer/kv_p2p/mooncake_connector.py:1655>)、[worker](<<redacted:local-path:b8dd889167fe>/vllm-ascend-kimi-k3-dspark/vllm_ascend/distributed/kv_transfer/kv_p2p/mooncake_connector.py:2058>)。启动前仍应在四节点检查这些端口未占用。

2. 验证必须真正要求 DSpark 产出 draft token

[validate-k3-dspark-pd.py](<<redacted:local-path:b8dd889167fe>/validate-k3-dspark-pd.py:271>) 目前只检查 `drafts > 0`。vLLM 的 `num_drafts` 每次观察都会加一，即使该次 draft token 数为零；应再要求：
