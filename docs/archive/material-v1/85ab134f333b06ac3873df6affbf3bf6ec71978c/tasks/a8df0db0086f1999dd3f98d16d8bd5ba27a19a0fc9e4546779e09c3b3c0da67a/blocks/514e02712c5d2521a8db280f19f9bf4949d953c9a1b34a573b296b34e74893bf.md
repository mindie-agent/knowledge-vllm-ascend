最关键的是 prefix cache：不能直接采用 PR #48459（`31b5bfe...`）。它只让 draft KV group 的 0-hit 不否决 target hit，却没有重建缺失的 aux hidden/draft KV。这样 target 命中但 draft miss 时，会分配全新 draft block，历史前缀 K/V 未写入，后续 draft attention 会读未初始化数据。

临时正确方案应满足：

- target prefix lookup 与 DSpark draft KV lookup 分开；draft group 不参与 target hit 收敛。
- scheduler/worker 显式携带 `target_hit` 与 `draft_hit`/`repair_start`。
- 对 `[draft_hit, target_hit)` 重建 draft KV。
- draft slot 必须来自 draft group 自己的 block table/block size。
- 只缓存 finalized context KV，不能缓存 noise/query/rejected slots。
- 若暂时不做 aux-hidden cache，则必须把有效命中回退到 `draft_hit` 并重算 target suffix；`draft_hit=0` 时有效命中必须为 0。性能下降可以接受，但不能伪造 warm hit。

若需要保留 target prefix 命中性能，v0.23 已有可复用基础：

- `HiddenStateCacheSpec`
- `CacheOnlyAttentionLayer`
- `extract_from_kv_cache`

可缓存 `combine_hidden_states` 后的 DSpark 输入 hidden，再据此执行 `precompute_and_store_context_kv` 修复 draft KV。

必要 prefix-cache 测试：

- target hit、draft miss
- target hit、draft partial hit
- 缺失 aux cache 时安全回退
- block 边界 `B-1/B/B+1/B+6/B+7`

- cold/warm 输出及 finalized draft KV 一致

- 最后再做四机 eager+greedy+prefix-on 验证和图模式验证。
