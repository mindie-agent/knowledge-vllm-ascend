### user
帮我找下dsv4用的moegatingtopk是在op-transformer里面还是ops-nn里面


### assistant:commentary
我先查一下 dsv4 的调用和本地算子源码，确认 `MoeGatingTopK` 归属。


### assistant:final_answer
在 **`ops-transformer`** 里，目录是 [`moe/moe_gating_top_k`](https://gitcode.com/cann/ops-transformer/tree/master/moe/moe_gating_top_k)。

DSV4 这里有个命名区别：

- **当前 vllm-ascend 的 DSV4 路径**调用 `moe_gating_top_k_hash`，使用 `norm_type=2`（sqrtsoftplus）。见[调用处](<redacted:local-path:22531ca92edb>:124)。
- **上游 ops-transformer** 将 Hash 功能放在同一个 `moe_gating_top_k` 目录，通过 `aclnnMoeGatingTopKV2` 提供。见[本地接口文档](<redacted:local-path:622e5ecf05ba>)。

找 DSV4 对应实现时，重点看 **V2、Hash 和 `normType=2`**。

### user
hash和softplus都是`aclnnMoeGatingTopKV2`吗


### assistant:commentary
我再核对一下 V1/V2 的接口和分发代码，确认 Hash 和 sqrtsoftplus 分别走哪条路径。


### assistant:final_answer
**两者都能通过 `aclnnMoeGatingTopKV2` 做，但 sqrtsoftplus 并非 V2 独有。** 按当前本地上游源码：

| 功能 | `aclnnMoeGatingTopK`（V1） | `aclnnMoeGatingTopKV2` |
|---|---|---|
| sqrtsoftplus，`normType=2` | 支持 | 支持 |
| Hash 路由 | 不支持 | 同时传入 `inputIdsOptional`、`tid2eidOptional` 开启 |
| sqrtsoftplus + Hash | 不支持 | 支持 |

Hash 决定**怎么选专家**，sqrtsoftplus 决定**怎么算专家分数**，两者可以组合。上游文档将 `normType=2` 标为仅支持 **Ascend 950PR/950DT（A5）**。见 [V1 文档](<redacted:local-path:8fb81306cf73>:40)、[V2 文档](<redacted:local-path:622e5ecf05ba>:124)。

补充澄清：你当前 **vllm-ascend 的 DSV4 实际调用仍是自带的 `aclnnMoeGatingTopKHash`**，还不是上游 V2。见 [C++ 调用](<redacted:local-path:ec13566b382a>:778)。
