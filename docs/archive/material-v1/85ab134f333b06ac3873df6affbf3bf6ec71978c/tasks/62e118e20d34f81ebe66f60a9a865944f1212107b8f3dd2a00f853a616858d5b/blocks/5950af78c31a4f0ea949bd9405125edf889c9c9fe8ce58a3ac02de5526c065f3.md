CLI / 会话边界：

- 顶层 **没有 `--cwd` / `--work-dir`**；TUI 从 `process.cwd()` 启动（`apps/kimi-code/src/cli/run-shell.ts:58`）。完整参数表在 `cli/commands.ts:39-118`。
- `kimi fork --cwd PATH` **只筛选待 fork 的旧 session**，不指定 fork 目标目录（`cli/sub/fork.ts:50-70,80-96`）。官方 fork 元数据继续使用原 workspace cwd（`workspace/sessionLifecycle/sessionLifecycleService.ts@6954d2c:641-645`）。
- `/new` 没有路径参数，仍用 TUI 当前 `appState.workDir` 创建（`tui/commands/dispatch.ts:464-478`；`tui/kimi-tui.ts:2253-2271,2297`）。
- 顶层不支持交互式初始 prompt 参数：`-p` 是非交互单次运行，位置参数被作为未知命令拒绝（`cli/commands.ts:63-65,158-160`）。生成首条提示词可以经宿主 ACP `session/prompt` 提交，但本身没有改根能力。
- 官方 **ACP `session/new`** 确实使用 `params.cwd` 创建 workspace/session（`packages/acp-server/src/server.ts:242-251`）；官方 SDK `createSession({workDir})` 同样可用（`packages/node-sdk/src/types.ts:217-227`）。
- ACP fork 的 cwd / additionalDirs / MCP 目标参数不会生效；load/resume 恢复原 session（`packages/acp-server/src/server.ts:255-320`）。
- resume 按原记录恢复 `summary.cwd`，不执行新建 prepare（`workspace/sessionLifecycle/sessionLifecycleService.ts:380-402`）。官方 TUI `-c` 只找当前目录，个人补丁才扩展到 worktree family；因此从主仓继续另一个 worktree 会话，仍需要启动方定位旧 cwd，或从该 worktree 启动。
