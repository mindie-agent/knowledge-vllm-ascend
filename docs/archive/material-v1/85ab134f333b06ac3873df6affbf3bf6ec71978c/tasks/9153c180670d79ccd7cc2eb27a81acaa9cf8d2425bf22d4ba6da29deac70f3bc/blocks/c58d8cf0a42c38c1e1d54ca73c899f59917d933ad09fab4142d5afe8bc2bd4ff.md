进程归属只依赖：

1. 环境变量 `VAWS_REMOTE_JOB_TOKEN`；
2. 原始 PGID 中未带 marker 的进程作为 `unknown`。

可执行命令：

```bash
setsid env -u VAWS_REMOTE_JOB_TOKEN sleep 60 &
```

若该命令由受管 shell 启动，外层 shell 会很快退出；`setsid` 子进程同时清除 marker 并切换 PGID。随后：

- `owned_processes()` 看不到该子进程；
- 它也不在原 PGID，因此不会进入 `unknown`；
- `job_status()` 可返回 `quiet=true` 且 `result=succeeded`；
- `.agents/lib/vaws_managed_execution.py:96-101, 156-180` 随后会进入 `_finish_managed()`，释放 lease 并归还 runtime。

这会使 detached、marker 被清除的后代继续运行而失去 managed cleanup。若后代仍占 NPU，物理占用探测可能阻止 release；但 CPU 后代或未被 occupancy parser 识别的进程会直接暴露此错误释放路径。现有 `managed_jobs` 测试覆盖了后台 descendant，但没有覆盖 `setsid + env -u VAWS_REMOTE_JOB_TOKEN`。
