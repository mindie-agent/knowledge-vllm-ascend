1. KDA kernel 卡死/invalid-GM；

## 为什么 0.26/13277 已修复，0.27 还会需要新修复

0.26 中 KDA 外层基本是一个不透明 CustomOp，图编译器看不到内部状态修改；0.27 把 causal-conv、recurrent KDA、norm、padding 等路径直接暴露在 FULL graph 中。

因此同一逻辑在两个版本下需要满足不同的图编译契约：

- 0.26 的 stream/event 生命周期修复不能自动保证 0.27 的 mutation schema 正确；
- 0.27 中输出别名、返回 tensor、状态 mutation 声明错误，可能只在 graph replay 中暴露；
- 但最新 r60 仍失败，说明我们目前修的这些 0.27 契约问题只是问题的一部分。

历史 0.26 精确 8K prefix-off 的 c1/c16 都没有退化；prefix-on c2 曾出现连续 `!`，而 c1 正常。当前 r60 是 c1、零命中就失败，所以不能简单复用当时的“并发 cache 生命周期”结论。

## 当前最大的四个 gap

1. **缺失当前版本的 eager 对照**

   154 只启动到中途，没有产生请求结果。这是当前最关键、成本最低的缺口。

2. **缺失 target-only 对照**

   当前失败同时启用了 target、DSpark、KDA、ACLGraph。必须关掉 DSpark，才能判断首 token 是否已经在 target 模型路径中错误。

3. **运行时不是完整 clean build**

   当前使用的是 vLLM 0.27.1、当前源码/新 Torch binding，加上旧的集成 vendor 包。完整 40-op rebuild 被无关的 GMM CANN 配置错误阻断。算子定向测试通过降低了风险，但还不能证明整套二进制完全匹配。

4. **权重基线没有严格对齐**

   当前是 16 专家裁剪 target + MLA draft；历史“0.26 高并发正确”和四机 GPQA 基线未必使用完全相同的 target/draft/QuaRot 文件。启动时还提示 target 缩减权重缺少可选 QuaRot 文件。它不能直接解释坏输出，但使跨版本结论不够严格。

本地代码分支当前是干净的；这里的问题是远端测试运行时的制品组合与历史基线没有完全同构，而不是本地未提交文件污染。

## 恢复后只需要做的最小实验

固定同一个源码、运行时 manifest、target/draft 权重和一个确定性首请求，只补下面三个格子：

|  | target-only | target + DSpark |
|---|---:|---:|
| eager | 未测 | **未完成，最先补** |
| 两张 ACLGraph | 未测 | **已确认失败** |

判断方式很直接：

- eager + DSpark 正常：继续锁定 ACLGraph。
- eager + DSpark 异常，但 eager target-only 正常：锁定 DSpark/KDA 集成或 draft 对齐。
- eager target-only 也异常：先查运行时制品、权重、target 模型及量化/AttnRes 路径。
- target-only eager 正常、graph 异常：锁定 target graph 数据流，而不是 DSpark。

每格先跑一个首请求即可，不需要再试五十次。首请求闭环后，才依次恢复 c16、prefix cold/hit、混部、两机 P/D；153/154 全部通过且 155 释放后，再进行四机 GPQA。
