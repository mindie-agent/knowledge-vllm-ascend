### 目标结构

建议拆为四个明确边界：

- 上游模型契约：K3 config、model、processor、原生 renderer/parser。
- Ascend 后端：KDA/MLA/MoE 设备实现和量化 adapter，不拥有 OpenAI 请求语义。
- Typed execution contracts：`MLAFeatureConfig`、`KdaExecutionPlan`，不再通过动态属性和 Optional/assert 组合。
- 单一注册入口：集中注册 config、model、renderer、reasoning/tool parser，不再依赖四个 side-effect patch 文件。

提交也应拆成独立纵向变更：serving 聚合、MLA typed contract、KDA plan、gate construction、测试清理、最后 upstream ownership。Mooncake、独立 SiTU、CI 等不属于 K3 模型适配的内容应拆出，但不能未经归属确认直接删除。

### 必须保留的行为

- 原生 tokenizer `apply_chat_template(tokenize=True)`，而不是简化 Jinja。
- 用户显式 native kwargs 优先；仅补缺省值。
- `tools + tool_choice=None` 才等价于 auto；无 tools 的 None 保持普通 chat。
- named tool 校验、`response_format`、流式/非流式 XTML 语义一致。
- K3 no-RoPE MLA slice、output gate、checkpoint state-dict 名称和 packed weights。
- K3 full-rank `g_proj`、A_log 128→96 裁剪及 TP shard；Kimi K2 行为不变。
- KDA state pool 按 `ssm_state_indices` 寻址；图 padding 空序列必须在读取 state metadata 前跳过。
- multimodal cached/uncached image token 展开完全一致。
- `_KimiRoutedOutputTransform` 当前承担非 owning module/fullgraph 语义，需等通用 MoE post-transform contract 就绪后再删除，不能当普通薄封装直接删。

### 推荐回归门槛

- 纯 UT：不可变 prompt options 全矩阵；XTML 在每个字符边界切 chunk；typed KDA plan 的合法/非法组合；state-dict 名称与 weight loader。
- NPU：非连续 recurrent 输入、prefill/decode/MTP、graph padding、混合 batch、eager 与 `FULL_DECODE_ONLY` 一致。
- 服务：thinking on/off，tools omitted/none/auto/required/named，single/multi tool，stream/non-stream，structured response，multimodal。
- 性能：删除 contiguous 前后 H2D/device copy、ACLGraph 节点数、parser 长输出延迟。
- 既有远端/NPU结果仅作为回归基线；本轮没有重新启动服务或重新跑设备验证。

另外，不应机械清除所有 `hasattr/getattr`：例如 `ops/kimi_kda.py:85-94` 检查 Torch schema 是否安装，以及 `kimi_k3_text.py:654` 遵循 vLLM `weight_loader` 约定，都是合理的边界能力检查。应删除的是用反射掩盖内部类型设计缺失的部分。
