### assistant:commentary
初步结论已经很明确：做。HCA/C128 不是“只有 128× 压缩后的全局注意力”；它还并行保留一条未压缩的短程 sliding-window 分支。现在我在核对窗口大小、拼接方式，以及不要把“压缩器的 128-token 状态窗口”误当成真正的 SWA。

### assistant:final_answer
结论：**做。** 更准确地说，C128/HCA 层是两条分支共同计算：

\[
\text{HCA}=
\underbrace{\text{所有已完成 C128 block 的稠密注意力}}_{\text{长程、压缩 KV}}
+
\underbrace{\text{最近 128 个未压缩 token 的 SWA}}_{\text{局部信息}}
\]

- C128 分支：每 128 个 token 压成一个 KV entry，对历史压缩 KV 做 dense causal attention；没有 C4/CSA 的 Lightning Indexer 和 top-k。
- SWA 分支：保留最近 128 个原始 token，包括当前 token，窗口代码语义是 `win_left=127, win_right=0`。
- 两部分 KV 一起进入同一次核心 attention，而不是先分别算两个 attention 再相加。

DeepSeek 官方技术报告明确写道，**CSA 和 HCA 都增加 sliding-window 分支**，窗口里的未压缩 KV 与压缩 KV 一起使用；Flash 和 Pro 的窗口大小均为 128。[DeepSeek-V4 Technical Report §2.3.3](https://arxiv.org/html/2606.19348)

这样设计主要是为了因果性：例如位置 100 的 query 不能使用第一个 C128 压缩 KV，因为该 KV 同时包含位置 101–127 的未来信息；SWA 分支让它仍然能够看到位置 0–100 的局部上下文。

当前 vLLM-Ascend 实现也能直接确认：

- 每个 DSV4 attention 层都会创建独立的 [`swa_cache_layer`](<redacted:local-path:768d37b4dde4>:588)。
- attention 调用同时传入 `ori_kv=swa_kv_cache` 和 `cmp_kv=compress_kv_cache`；SWA 使用滑窗 mask，压缩分支使用 causal mask。[dsa_v1.py](<redacted:local-path:140757172e15>:1514)
- 只有 C4 设置 `cmp_sparse_indices`；C128 不设置，因此是“压缩历史 dense attention + SWA”。[dsa_v1.py](<redacted:local-path:140757172e15>:1582)

所以一句话：**HCA 做 SWA，但 C128 压缩分支本身不是 SWA；HCA 层由 C128 全局压缩分支和 128-token 局部 SWA 分支组成。**

### assistant:final_answer
对，你说的是“压缩主分支”，这点没错。关键是不要把压缩方式和整层的全部 attention 分支混在一起。

| 类型 | 长程压缩分支 | 局部未压缩分支 |
|---|---|---|
| C1 / pure SWA | 无 | 最近 128 token 的 SWA |
| C4 / CSA | 压缩率 4：实际是宽度 8、stride 4 的重叠加权池化，再 top-k | 最近 128 token 的 SWA |
| C128 / HCA | 每 128 token 非重叠地加权合并成 1 个 KV，对全部历史压缩 KV 做 dense attention | 最近 128 token 的 SWA |

所以你说的：

> C4 和 C128 会把每 4/128 个 token 合并

作为简化理解是对的。更精确地说，C4 是“每前进 4 token 生成一个压缩 KV”，但池化窗口覆盖 8 token；C128 才是严格的 128 token 非重叠合成一个。

分歧点在于：**C4/C128 标签描述的是长程压缩分支，不代表整层只有这个分支。** DeepSeek 官方报告明确说明，CSA 和 HCA 都额外带一条 SWA，最近 128 个未压缩 KV 会和压缩 KV 一起参与核心 attention。[DeepSeek-V4 报告 §2.3.3](https://arxiv.org/html/2606.19348)

当前实现也把三类明确写成：

- `sliding`
- `sliding + CSA`
- `sliding + HCA`

[Transformers DeepSeek-V4 参考实现](https://github.com/huggingface/transformers/blob/main/src/transformers/models/deepseek_v4/modular_deepseek_v4.py)

在 Ascend CP 路径里尤其直观：

- C1：只传 `ori_kv=swa_kv_cache`
- C4：传 `ori_kv + cmp_kv + cmp_sparse_indices`
- C128：传 `ori_kv + cmp_kv`，不传 indexer 结果

对应代码在 [dsa_cp.py](<redacted:local-path:f62755d8312a>:1626)。

所以最终应当记成：**C1 是纯 SWA；C4 是 C4 sparse + SWA；C128 是 C128 dense + SWA。**
