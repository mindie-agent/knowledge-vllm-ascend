- `s7×t1×h6` 对应 42 个 sequence-head 工作项；Triton grid 是 `(2,42)`，各 program 独立，不复用 AscendC 的 ping-pong/cross-core flag，因此很适合作反向验证。
- 推荐阈值矩阵是 `N=1,4,5,7`：分别为 6/24/30/42 tasks，能直接检查跨过 24-core 后才失败的假设。

可直接依次运行：

```bash
export TASK_QUEUE_ENABLE=0
export ASCEND_RT_VISIBLE_DEVICES=0

timeout -k 15s 300s python probe_chunk_kda_multiseq.py \
  --phase gate --sequences 7 --tokens-per-sequence 1 --heads 6

for n in 1 4 5 7; do
  timeout -k 15s 300s python probe_chunk_kda_multiseq.py \
    --phase triton-fwd-h \
    --sequences "$n" --tokens-per-sequence 1 --heads 6
done

timeout -k 15s 300s python probe_chunk_kda_multiseq.py \
  --phase compare-triton-fwd-h \
  --sequences 7 --tokens-per-sequence 1 --heads 6
```

其中 `compare-triton-fwd-h` 使用 7 次独立 AscendC N=1 作为 reference，再比较 Triton N=7，避免 reference 本身进入可疑的 42-task 调度。

判定：

- AscendC N4 通过、N5/N7 卡住，而 Triton 全通过且精度一致：强指向 AscendC H 子算子多任务/ping-pong 调度。
- 两种 H 都通过、只有原生完整 `chunk_kda_fwd` 卡住：转查 H 前后的 stage-3/stage-2 或 composite orchestration。
- 单算子均通过、仅服务卡住：转查多层调用、stream/graph 或其他算子。
