2. 多 step 会不会刷新

   - 普通 forward：创建新的 `ForwardContext`，缓存重新开始。
   - 同一 context 内的多个 MTP 子步：切换 metadata 后显式清缓存。[子步刷新](<redacted:local-path:d17fe326ad14>:1524)
   - ACLGraph replay：不重新执行 Python 缓存判断，而是重新执行捕获的 metadata 算子、更新固定地址中的值。因此还要验证输入 buffer 每步更新正确，不能只看地址不变。

3. 现有证据到哪里

   C4 两条路径和 C128，在 4 个 TP rank 上的**首次存入／首次读取／重新计算**采样值一致。但探针跳过后续层，同一图形状只 dump 一次；这轮只有一个真实请求，padding 后 `num_reqs=2` **不算两请求并发验证**，MTP1 也没有覆盖多个 draft 子步。[验证记录](<redacted:local-path:5f1a53c0d690>:17)

所以还不能排除后续层读错、跨 step 陈旧值或并发时请求行错配。要回答“全部正确”，下一轮需要逐层、逐用途、连续多步比较，并加入不同长度请求的并发及进出 batch；仍然图内抓 device 快照、图外落盘。这验证的是 metadata 复用一致性，不是整个 compressor／indexer 输出精度。
