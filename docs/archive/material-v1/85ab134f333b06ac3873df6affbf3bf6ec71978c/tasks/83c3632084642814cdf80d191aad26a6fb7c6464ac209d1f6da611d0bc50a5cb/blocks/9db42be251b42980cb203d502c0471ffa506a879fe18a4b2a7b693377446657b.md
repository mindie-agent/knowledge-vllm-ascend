我核对的是最新 `origin/releases/v0.23.0_ci_new`：`17cb94b9`。

- Block Table 可以按逻辑列切分。物理 block ID 不连续不影响，只要保持表内顺序。当前 block size 是 128，400K token 约 3125 blocks；32 路时每路最多 98 blocks，需要给尾部补 11 个 table slot，但不需要复制 KV Cache。
- 合并公式正确：`L = logsumexp(L_i)`，`O = Σ exp(L_i-L) O_i`。仓库已有 FIA 返回 LSE 后调用 `torch_npu.npu_attention_update` 的实现，可直接复用思路：[chunked-prefill 合并路径](<<redacted:local-path:b8dd889167fe>/vllm-ascend-kimi-k3/vllm_ascend/attention/mla_v1.py:1153>)。
- 当前常规 decode 直接调用 `torch_npu.npu_fused_infer_attention_score_v2`，并没有经过仓库自己的 C++ binding：[decode FIA 路径](<<redacted:local-path:b8dd889167fe>/vllm-ascend-kimi-k3/vllm_ascend/attention/mla_v1.py:1457>)。

需要修正几个设计点：

- 不只是广播一个 Query；当前要同时扩展 `q_nope` 和 `q_pe`，实际布局接近 `[B, H, 1, D]`。算子通常要求连续内存，所以最终可能需要一个很小的 Query `.contiguous()` 拷贝。
- 每个分片长度应为  
  `local_len = clamp(context_len - split_id * chunk_capacity, 0, chunk_capacity)`。
- 空分片不能直接参与合并：其 LSE 必须排除或设为 `-inf`。
- `32 核 ≠ 32 splits 一定最优`。FIA 内部本身会切核，建议实测 `8/16/32/64`；64 路会增加 Query、局部输出和 Reduce 开销。
- 第一版应限制在单 token decode、无 mask/sliding-window、长上下文；不要一开始覆盖 speculative decode 和复杂 batch。

最大风险是 LSE。公开接口本身已经有 `return_softmax_lse`，所以“修改 C++ bound 才能吐 LSE”未必成立。[官方 FIA v2 接口](https://gitcode.com/Ascend/op-plugin/blob/7.3.0/docs/context/torch_npu-npu_fused_infer_attention_score_v2.md)也定义了 float32 LSE 和 S 轴外切能力。但公开文档对 K3 类似的 `D=512 + rope D=64 + PageAttention` 组合明确标记为不支持开启 softmax LSE；A5 当前 CANN 版本可能已经变化，必须在机器上实测确认。[约束说明](https://www.hiascend.[REDACTED_SECRET].md)

建议先做一个不改主代码的 A5 单算子探针：

1. 原样调用当前 FIA v2，开启 `return_softmax_lse=True`。
2. 检查 LSE 是否为 float32、形状 `[B,H,1,1]`，有效行是否 finite。
3. 比较未切分结果与“32 路切分 + `npu_attention_update`”数值。
4. 验证 `.out`、workspace 查询及 ACLGraph replay。

如果探针通过：eager 原型约 1 天，补齐 ACLGraph 参数更新、buffer 预分配、单测和 A5 数值/性能验证，整体大约 3–5 个工作日。ACLGraph 是主要代码量，因为当前 replay 会单独更新 `block_table`、`seq_lens_list` 和 workspace：[图参数更新](<<redacted:local-path:b8dd889167fe>/vllm-ascend-kimi-k3/vllm_ascend/attention/mla_v1.py:802>)。

如果探针表明该 MLA+PA 路径没有真实 LSE，单改 binding 没用，需要 CANN FIA kernel/tiling 支持或换算子路径，那就不是一个 ci-new 小补丁了。

### assistant:commentary
代码里已经有一个很强的先例：`mla_cp` 在 ACLGraph 捕获路径中就是“FIA 输出 LSE → 整理 TensorList → `npu_attention_update`”，并且 replay 时通过 graph task update 更新 KV 长度。因此 Reduce 入图不是架构性障碍；需要重点处理的是固定分片形状、图缓存键，以及 A5 FIA v2 的真实 LSE 能力。

### assistant:final_answer
结论：可以适用于 `FULL_DECODE_ONLY` ACLGraph，而且 `ci-new` 已有非常接近的模板；但必须把分片做成“静态图结构”，不能在同一张图里根据长度动态切换 `N=1/32/64`。

现有依据：

- 常规 MLA 已通过 `graph_task_group` 捕获 FIA，并在 replay 前用 `graph_task_update` 更新 `block_table` 和 `seq_lens`：[mla_v1.py](<<redacted:local-path:b8dd889167fe>/vllm-ascend-kimi-k3/vllm_ascend/attention/mla_v1.py:803>)。
- CP MLA 的 ACLGraph 路径已经在做“FIA 返回 LSE → `npu_attention_update` 合并”：[mla_cp.py](<<redacted:local-path:b8dd889167fe>/vllm-ascend-kimi-k3/vllm_ascend/attention/context_parallel/mla_cp.py:613>)。因此 Reduce 入图不是架构性障碍。

建议的图内结构是：

```text
q_nope/q_pe
    │ broadcast + contiguous，固定 N=32
    ▼
[B*32, H, 1, D]
    │
    │ FIA v2，固定输出地址
    ▼
local_out + float32 local_lse
    │ reshape/permute/contiguous
    ▼
32 个静态 Tensor view
    │
    ▼
npu_attention_update
    │
    ▼
[B, H, 1, D] → 原来的 v_up_proj
```

需要做四处适配：

1. Block Table 静态化

把每行最大 block 数在初始化时向上补齐到 `num_splits` 的倍数。例如 3125 补到 3136，然后直接：

```python
split_table = block_table.view(B * 32, 98)
```

这样 replay 时仍由现有 `commit_block_table()` 更新原始固定 buffer，不需要复制 KV，也不需要每层复制 Block Table。

2. Capture 输出和 workspace

当前 graph 路径里的 `softmax_lse` 只是一个和 `num_tokens` 等长的占位 tensor，并且没有开启真实 LSE。需要：

- FIA v2 capture 和 task update 都传 `return_softmax_lse=True`。
- LSE 预分配为 float32 `[B*32, H, 1, 1]`。
- workspace 查询使用分片后的 Query/Table 形状。
- `npu_attention_update` 的 TensorList 长度固定为 32。

3. Replay 参数更新

`update_graph_params()` 每轮在 Host 侧计算：

```python
local_len[b, i] = clamp(
    seq_len[b] - i * chunk_capacity,
    0,
    chunk_capacity,
)
```

然后把固定长度 `B*32` 的列表交给 FIA task update。Reduce 的输入地址和个数已经在 capture 时固定，不需要单独 update。

4. 图缓存键

当前 `GraphParams` 主要按 `num_tokens` 保存：[acl_graph.py](<<redacted:local-path:b8dd889167fe>/vllm-ascend-kimi-k3/vllm_ascend/compilation/acl_graph.py:292>)。因此同一个 batch graph 不能这次 `N=1`、下次 `N=32`。

最简单的 400K 方案是：

- 服务启动时固定 `num_splits=32`；
- 长上下文 decode graph 始终走分片；
- 第一版不支持运行时切换 32/64。

如果同一服务要高效混跑短、长上下文，就需要把 `fia_split_mode/num_splits` 加入 graph key，分别捕获 unsplit 和 split graph，这会扩大改动面。否则只能始终分片，短序列会浪费计算。

仍需在 A5 上验证三个硬门槛：

- FIA v2 的 K3 MLA+PageAttention 路径能否真实返回 LSE；公开接口有 LSE 参数，但公开文档对类似 `D=512 + rope D=64 + PA` 组合存在不支持说明。[FIA v2 接口](https://gitcode.com/Ascend/op-plugin/blob/7.3.0/docs/context/torch_npu-npu_fused_infer_attention_score_v2.md)
- `npu_attention_update` 能否以 32 个输入完成 capture/replay；64 路不要先默认可用。
- graph capture batch 为 32 时，FIA 有效 batch 会变成 `32×32=1024`，需要检查 workspace、图内存和 stream resource。

所以最终判断是：ACLGraph 适配是可行的，且不需要推翻现有框架；如果 A5 LSE 探针通过，主要是 Python graph plumbing 和 buffer 设计。若 LSE 不支持，修改 ACLGraph 或普通 C++ binding 都解决不了，仍然需要底层 FIA 算子支持。
