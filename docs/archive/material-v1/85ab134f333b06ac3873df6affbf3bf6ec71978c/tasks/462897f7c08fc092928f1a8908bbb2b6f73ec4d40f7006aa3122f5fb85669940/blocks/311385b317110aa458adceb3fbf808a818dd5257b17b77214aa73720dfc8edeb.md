### assistant:final_answer
只读审查完成。**显式人工恢复可以直接复用 `prepare` / `install`，但只有这两行不够。**不需要删除 attempts、修改 `next_check` 或重新注册 scheduler。

1. **在最终合并 SHA 明确后，用该 SHA 的干净、已审查源码加载 `Updater`。**不能使用当前未正式合并的 `783190b` 代替最终 SHA。

2. **先拿 `checker.lock`，然后重新加载 settings/state。**旧 `33de369` 的 `check()` 也使用这个锁并在锁内重读 state，足以串行化 updater 的插件检查/安装。`file_lock` 本身不重入，锁内不要再调用 `check()`。锁顺序保持 `checker → update`。[check 实现](<redacted:local-path:75a5cb8793db>:1229)、[锁实现](<redacted:local-path:77db58afb083>:25)

3. **先检查遗留事务。**有 `transaction.json` 时，在 `update_lock(config, exclusive=True)` 下调用 `recover()`；恢复失败就停，保留 journal。不能让 `install()` 用新 journal 覆盖未处理的旧事务。恢复后重读 current、adapter 和 native inventory；若最终 SHA 已提交且原生版本/字节验证成立，应作为已完成恢复结束，不能重复安装。[recover](<redacted:local-path:75a5cb8793db>:945)、[install 写 journal](<redacted:local-path:75a5cb8793db>:1058)

4. **调用 `resolve()` 并要求结果等于 root 提供的最终 SHA。**它只解析 channel，不检查 attempts，也不修改 `next_check`。不相等则停，不追随更新后的 main。[resolve](<redacted:local-path:75a5cb8793db>:480)

5. **检查目标 generation 后再 `prepare(finalSHA)`。**
   - 新鲜准备路径已检查 fetch 后 HEAD、源码 contract，并用候选解释器运行新 probe；无需再探测已知不兼容的旧运行时。[准备验证](<redacted:local-path:75a5cb8793db>:622)
   - **已有 `prepared.json` 会被无验证、无 probe 地直接返回。**最小安全方案是遇到它就停止并保留现场，另行核对 receipt、源码、候选路径/字节、依赖及候选 probe 后才能复用；不能以“调用过 prepare”当作重新验证。[直接复用分支](<redacted:local-path:75a5cb8793db>:597)
   - 若目录存在但没有 receipt，`prepare` 会删除目录重建；事先必须确认它不被 current、adapter 或尚未解决的事务引用。[删除 staging 分支](<redacted:local-path:75a5cb8793db>:602)

6. **调用一次 `install(candidate)`。**它自行拿 exclusive update lock，执行 idle/stop、事务、原生版本与字节验证、adapter 切换及服务恢复。不要外包 shared update lock；同线程 shared→exclusive 会立即失败。准备阶段只持 checker 锁即可。[install](<redacted:local-path:75a5cb8793db>:1005)、[禁止换锁模式](<redacted:local-path:77db58afb083>:98)

7. **人工操作必须单独留可读 receipt，并保留原 attempts。**调用前记录人工恢复原因、最终 SHA、原 attempts/current、阶段；失败记录异常类型、消息及完整 `__cause__`/`__context__` 链。`install` 的 `recover()` 或最后 `restore_caches()` 可能再次抛异常，单独记最外层异常会丢失首因。区分：
   - `waiting_for_idle`：未完成；
   - `degraded` 或 current 已提交后的清理错误：安装可能完成、后续步骤失败；
   - 未知外部结果：保留 journal/inventory 证据，禁止直接重复安装。
   
   若更新 updater state，只用其 `save()` 合并必要状态，保留 attempts 与原 `next_check`；不要调用会改调度时间的 `_note_resolve_failure()`。[异常与 finally](<redacted:local-path:75a5cb8793db>:1166)、[save](<redacted:local-path:75a5cb8793db>:446)
