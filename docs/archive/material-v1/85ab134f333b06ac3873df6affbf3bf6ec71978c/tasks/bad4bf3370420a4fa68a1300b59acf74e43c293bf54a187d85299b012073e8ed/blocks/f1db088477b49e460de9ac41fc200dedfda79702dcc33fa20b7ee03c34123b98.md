**怎么切**
SRA 切的是完整的 **`(ngram 阶数, hash head)` 对应的 bucket**，不是 embedding 的通道维：

```text
H = (engram_max_ngram_size - 1) × engram_n_heads
分片数 R = TP × 节点内参与共享的 DP 数

每个 rank 持有若干完整 head 的表，仍放在 HBM。
```

这样一个 head 的查询永远由固定 rank 处理，不再按每个 hash ID 临时算 owner、交换 counts、生成变长 split sizes。[SRA #67](https://github.[REDACTED_SECRET])、[#74](https://github.[REDACTED_SECRET])

需要用实际 checkpoint 的 `H` 核对分片组合：SRA 当前的 `ceil(H/R)` 切法还有“不能留下空 rank”的限制，不能直接假设所有 TP/DP 组合都成立。

**建议方案**
1. **Hash/history 全部搬到 NPU。**  
   参考 [#49](https://github.[REDACTED_SECRET])，用 Triton 维护按 SWA 物理 slot 索引的 token history，再计算两层 Engram 的 hashes 和 mask。直接使用设备上的 token IDs、positions、block table，消掉现在的三次输入 D2H。

2. **HBM 表改成 head 分片，保持量化格式。**  
   loader 按 head bucket 的连续行区间加载 BF16/INT8 权重及 scales。节点内仍只保存一份完整表，不退化成每个 DP 各存一份。

3. **用定长设备通信替代变长 routing。**
   ```text
   NPU hash
     → 节点内 DP all-gather hashes（按已有 DP token 数 padding）
     → 每个 rank 查自己持有的 heads
     → DP 交换结果，保留本 DP 的 tokens
     → TP 汇齐 heads
     → 现有 WKV / gate
   ```
   删除 CPU counts、排序 permutation、metadata H2D/D2H，以及 Python split-size 路径。首版保持现有 WKV/gate/SP 行为，不同时改投影并行。

4. **保留必要的状态语义。**  
   覆盖 chunked prefill、prefix 命中、DSpark 回退重写、图回放和 idle DP。特别是 P/D 外部加载的 KV 不自带 hash history，需要补 lookback；SRA V1 也为此从 runner 提供 prompt lookback，不能只搬 hash kernel。

**目标是 HBM Engram 稳态路径没有 host-blocking 的 H2D/D2H，也不读取设备标量决定通信形状。** 初始化加载、必要的输入上传与设备间通信不属于要“全部消失”的部分。
