- **Grok 原生偏好只覆盖 `/new`、`/fork`。**  
  `~/.grok/docs/user-guide/05-configuration.md:425-438` 说明 `[hints] new_session_worktree_mode = "always"` 和 `fork_worktree_mode = "always"`。文档列的是全局配置合并，不能假定写项目 `.grok/config.toml` 就生效，也不应为了 VAWS 悄悄改变其他项目的默认行为。
- **Grok hook 可以补上下文，不能选目录。**  
  `10-hooks.md:478` 明确 SessionStart stdout 被忽略；`10-hooks.md:266-279` 明确 PreToolUse 可以改 `updatedInput`。现 coordinator hook `:127-149` 已用这个能力注入 VAWS context。新会话默认 worktree 基于当前 HEAD；`--worktree-ref` 是 CLI 参数，没有找到原生默认主仓基线或 WorktreeCreate/setup hook。
- **Kimi 已准确对应已装版本源码。**  
  `0.42.0` tag 是 `6954d2c8bf94a5c7fc29cc6ae35b15d042cc4dcb`。其 [SessionExternalHooksService](https://github.[REDACTED_SECRET].ts) 在 `onDidCreateSession` 后调用 hook，并等待完成；返回值没有被用于修改会话。`this.context.cwd` 此时已确定。**不是 hook 一定不等待，而是等待也不提供 cwd/env 修改能力。**
- **Kimi fork 不发 SessionStart。**  
  上述源码明确 `event.source !== 'fork'` 才触发。当前 coordinator `UserPromptSubmit` 直接查已有 attachment（`:113-119`），因此原生 fork 的新 ID 可能一直找不到关联。可在首次带稳定原生 ID 的正常事件中幂等补关联，不能按 cwd/最近会话推断。
- **Kimi 子 Agent 缺稳定身份。**  
  当前 `SubagentStart` 输入只有 `agentName`、`prompt` 等，没有子 Agent ID；coordinator `:105-107` 会正确拒绝用展示名冒充身份。不能宣称已覆盖。
- **Kimi 当前不能无感注入 MCP context。**  
  [HookResult](https://github.[REDACTED_SECRET].ts) 没有 `updatedInput`、cwd、env 返回字段；[MCP stdio](https://github.[REDACTED_SECRET].ts) 的调用只发送 tool name/arguments，连接按 workspace/runtime 创建，没有逐会话 ID。当前通过 UserPromptSubmit 提示 Agent 传 context 的方式确实仍有 Agent 负担。[官方 hook 文档](https://moonshotai.github.io/kimi-code/en/customization/hooks) 与此一致。

建议主线：把“选择更新版本 → 创建目录 → 固定环境 → 原生 new-session 请求”放进**宿主客户端创建会话的真实入口**，现有 SessionStart 只负责记录原生 ID 和实际 cwd。CLI 保留为可选入口。Grok/Kimi 当前缺少可配置创建前扩展，宜在能力表中明确缺口；不要用 hook 偷改工作目录、改写所有工具路径或按 cwd 猜身份来伪装覆盖。

现有 `AgentSessions.attach` 已自动创建本地 VAWS task，无需 Agent 再调用 `vaws_session` 才算初始化；`vaws_session` 继续用于按需查看/配置执行上下文即可。
