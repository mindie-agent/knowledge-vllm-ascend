这个划分有价值，关键是把“曾经发生过”与“现在仍成立”明确分开。建议守住五点：

1. **经验保留事件，知识维护结论。** 经验写当时的条件、操作、观察结果和证据；知识写当前适用的原理、约束和做法。两者用链接关联即可，同一个检索入口、普通 Markdown 足够。

2. **经验也要纠错。** “修改后恢复正常”可以是观察事实，“根因就是这处代码”可能只是推断。后来发现判断错误时，保留过程并显著更新最终结论，不能因为属于历史就让错误归因永久有效。

3. **检索时明确用途。** 默认回答当前实现时优先提供知识；排查相似问题时返回经验，显式带上时间、版本、适用条件及后续修正。旧经验中的命令和绕过方案应被理解为当时采取的操作，不能自动成为当前执行建议。

4. **复用上一轮筛选结果，改变去向即可。** 19 条保留稿继续作为当前知识候选；被剔除的旧实现或已修复故障，若有独特诊断过程和可信证据，可整理为经验。重复内容仍合并；未闭环案例必须标明未解决或未证实，不能包装成成功经验。无需把所有淘汰项原样恢复。

5. **经验积累后再抽象。** 多次出现相同判断步骤时考虑 skill；步骤稳定、输入输出明确时再抽工具。现在只保留有启发的过程和证据，不增加提前抽象、复杂分类或额外维护负担。
