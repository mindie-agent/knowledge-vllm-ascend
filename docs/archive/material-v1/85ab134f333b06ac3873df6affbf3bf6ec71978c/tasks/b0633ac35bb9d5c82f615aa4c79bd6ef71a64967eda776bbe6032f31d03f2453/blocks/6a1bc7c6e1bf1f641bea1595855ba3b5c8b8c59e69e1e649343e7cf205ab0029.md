- Dense/Attention：维持全局 `TP16 × DP4`
- MoE 的 expert 数量：沿 DP 轴切成 `EP4`
- 每个 expert 的权重：沿 TP 轴再切成 `expert-TP16`

因此逻辑上是：

```text
MoE expert shards = EP4 × expert-TP16 = 64
```

而不是：

```text
DP4 × TP16 × EP4 = 256
```

当前与改造后的区别是：

```text
当前 EP64：
896 / 64 = 每张卡 14 个完整 expert
```

```text
改造后 EP4 × expert-TP16：
每个 TP16 group 负责 896 / 4 = 224 个 expert
每张卡保存这 224 个 expert 的 1/16
等价于每张卡仍保存约 14 个完整 expert 的参数量
```

通信会从当前的一维 EP64 变成分层通信：

1. Token dispatch 在 `EP4` 之间进行，把 token 发给 expert owner。
2. 同一 expert 的 16 个 TP rank 共同计算其 GMM。
3. expert 内部通过 TP collective 合并 partial。
4. Token combine 再沿 EP4 返回原 DP rank。

这样 routed down/up projection、expert GMM 和 dense 模块可以统一使用同一组 TP16。代价是现有 AllToAll/MC2/AllGather dispatcher 都需要理解二维 `EP4 × expert-TP16`，不能再假设“一个 expert 只归属于一张物理卡”。
