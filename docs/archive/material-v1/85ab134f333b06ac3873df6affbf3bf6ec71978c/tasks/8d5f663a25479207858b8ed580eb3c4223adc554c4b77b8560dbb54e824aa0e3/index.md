# 轻量经验收集与摘要成本评估

当前任务聚焦于低存储、低算力的 GitHub 经验分发架构：保留可分享的脱敏经历，允许失败、误判和不完整内容，使用低成本摘要辅助检索而非产出已验证结论。已有实现方向包括限制摘要输入至 12 KiB、保留完整正文和复用缓存，但这些结果主要来自合成测量与本地测试，真实 Luna 调用、质量、费用和中段信息遗漏仍待系统评估。

## Materials

- [轻量经验架构与成本约束](blocks/4261680e1c978a36263a12d2728c0ab0a31d159c8c5c2e3258ec7c4f09357349.md): 讨论了以中心 GitHub 仓库存储和分发经验、由用户承担低成本摘要、允许错误与失败经验作为参考的架构取舍。此前较重的方案包含完整经验提炼、证据核验和质量评测，但后续判断其成本超出需求；更轻量的方向是保留脱敏正文，仅生成粗粒度检索头部，并明确摘要覆盖不完整。该方向及真实模型质量、成本尚未完成验证。
- [摘要输入裁剪与 Luna 评估](blocks/b15d9f4792cd223dabd20922c923257b0db2273c9c4228410dd1812cf70a813b.md): 提出默认采用已有经历正文、低成本检索头部和增量 GitHub 维护，机械整理负责范围控制与确定性去重，小模型只生成标题、摘要和关键词。后续本地重构报告了 12 KiB 首尾采样、正文保留、摘要缓存复用及测试通过，但真实模型调用、安装切换、实际费用和摘要质量仍未验收。当前待评估问题是 Luna 小模型生成摘要与全文输入、首尾采样或增量摘要相比，在中段关键发现、遗漏、成本和检索效果上的差异。
