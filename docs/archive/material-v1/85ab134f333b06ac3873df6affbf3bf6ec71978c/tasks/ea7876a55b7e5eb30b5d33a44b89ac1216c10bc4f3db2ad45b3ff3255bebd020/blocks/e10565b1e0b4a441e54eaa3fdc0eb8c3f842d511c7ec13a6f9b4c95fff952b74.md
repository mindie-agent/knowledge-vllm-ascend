对，这就是当前最核心的因果链，不能只说“换了 KV 以后恰好暴露另一个死锁”。

现在证据支持的解释是：

- 改 KV 前，问题是 **合法地址范围内的物理 block 踩踏**：compact GQA 用较小 stride 解释共享 backing，不同逻辑 block 会写到同一物理区域。算子仍能完成，所以表现为精度错，而不是卡死。
- 改 KV 后，padding 把一个 scheduler parent 映射成多个 kernel block，并把 GQA 的全局 K/V 纳入新 block 清零；这第一次引入了“MLA 与 GQA 不同 page size、并且异步批次并发清零”的新执行路径。
- R14 相对无卡死基线的生产差异确实只剩 **planner + zeroer**。首个失败 batch 恰好有 6–8 个 `new_block_ids_to_zero`，随后 `execute_model` 已返回，`sample_tokens` 等不到 NPU worker；四个 DP 都一致。因此卡死是 KV 改动经 zeroer/异步流引入的，不是无关的 DP 调度问题。
- 当前 zeroer 同时偏离上游两个关键契约：把不同 page size 塞进一个动态 kernel；以及复用单个 nonblocking H2D 的 pinned/device ID buffer。旧路径没有这组条件，所以可能只有踩踏精度问题；新路径会把 NPU stream 卡住，最终表现为 `sample_tokens` 超时。
