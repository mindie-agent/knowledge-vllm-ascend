### 1. 最终 PR 树的实际热点

调用链：

- KDA layer 由 [kimi_k3.py:881](<redacted:local-path:0b806b066b9d>:881) 实例化。
- OOT 替换为 Ascend 实现：[utils.py:731](<redacted:local-path:7b135b3053cd>:731)。
- Q/K/V 激活来自三个 TP ColumnParallel projection，随后在 [kimi_kda.py:443](<redacted:local-path:67927c034326>:443) 合并。
- 权重每次在 [kimi_kda.py:273](<redacted:local-path:67927c034326>:273) 重新打包，并在 [kimi_kda.py:444](<redacted:local-path:67927c034326>:444) 每层、每次 forward 无条件执行一次。

TP16 的生产 shape：

| 对象 | shape | stride / 行为 |
|---|---:|---|
| 单个 q/k/v projection | `[N, 768]` | 动态激活 |
| `mixed_qkv` | `[N, 2304]` | `torch.cat` 后 contiguous，stride `(2304, 1)` |
| 单个 conv 参数 | `[768, 1, 4]`, FP32 | stride `(4, 4, 1)` |
| squeeze/view | `[768, 4]` | stride `(4, 1)` |
| transpose view | `[4, 768]` | stride `(1, 4)`，本身不复制 |
| 三权重 cat | `[4, 2304]`, FP32 | 新 contiguous tensor |
| dtype cast | `[4, 2304]`, BF16 | 第二个新 contiguous tensor |

因此真正的运行时开销并不是 `transpose` 元数据本身，而是它后面的三权重 `cat` 和 FP32→BF16 cast。末尾 `.contiguous()` 对当前 cat/cast 结果通常是 no-op。

K3 有 69 个 KDA 层；每个 rank 每次完整 forward：

- 69 次权重 pack。
- 每层产生 36,864 B 的 FP32 cat 和 18,432 B 的 BF16 cast。
- 合计约 3.64 MiB 临时输出/rank/forward。
- 四机 64 rank 的逻辑临时输出量约 232.9 MiB/forward。

同一层即使同时有 spec 和 non-spec 分支，权重只 pack 一次并复用；但仍会在下一次 forward 再 pack。

### 2. 其他 transpose/contiguous 的判断

- [kimi_kda.py:209](<redacted:local-path:67927c034326>:209) 的 `hidden_states.contiguous()` 是动态 FlashComm/all-gather 边界。已 contiguous 时无复制，不能移到 init/load。
- causal-conv 前没有 activation `transpose` 或 `permute`；`mixed_qkv` 已是 kernel 需要的 `[N,C]` contiguous 布局。
- conv state shape 由 [kimi_kda_state.py:41](<redacted:local-path:c68889802884>:41) 决定，并直接传给 CANN，没有运行时 transpose。K=7 时每 slot 的 state window 为 `4-1+7=10`。
- causal-conv 后，Q/K/V 是 mixed tensor 的 chunk view，送 recurrent/prefill 前的三个 `.contiguous()` 是实际动态复制；不能在 load 阶段消除。
- [kimi_kda.py:367](<redacted:local-path:67927c034326>:367) 和 [kimi_kda.py:414](<redacted:local-path:67927c034326>:414) 的 recurrent state transpose 是可变状态在 `[H,V,K]` cache 与 `[H,K,V]` prefill kernel 间转换。只能通过改 recurrent kernel 或全局 cache layout 消除，不适合这个 commit。
- `A_log.reshape(-1).contiguous()` 与 `dt_bias.contiguous()` 当前参数本身连续，基本是 view/no-op，不值得单独缓存。
- 最终 KDA 文件中没有 `permute`。

### 4. 推荐的第 11 commit 最小方案

仅改 `vllm_ascend/ops/kimi_kda.py`：

1. `__init__` 预分配一个 `persistent=False` buffer：

   - shape `[conv_size, 3 * local_num_heads * head_dim]`
   - TP16 即 `[4,2304]`
   - dtype 为 model dtype，当前即 BF16
   - contiguous、kernel-native `[W,C]`
   - 每层 18 KiB，69 层合计约 1.21 MiB/rank

2. 包装现有 q/k/v conv parameter 的 `weight_loader`：

   - 先调用原 loader，保留 upstream TP shard 逻辑。
   - 再将该 local shard transpose 后 `copy_` 到固定 buffer 的 q、k 或 v column slice。
   - 每个 loader 只更新自己的 slice，不读取尚未加载的另外两个参数。
   - 必须原地 `copy_`，不能重新赋值 buffer，以保持 ACLGraph 捕获地址稳定。
   - 这样正常加载和 layerwise reload 都能刷新缓存。

3. `_conv_weights_t()` 直接返回缓存，并保留一次性 lazy fallback：

   - 覆盖 dummy loader 或绕过 weight loader 的特殊加载路径。
   - 校验 shape、dtype、device。
   - fallback 也只能原地填充预分配 buffer。

不建议把 KDA 粗暴加入通用 `process_weights_after_loading` 的 `device_loading_context`。当前 walker 位于 [patch_process_weights_after_loading.py:24](<redacted:local-path:cb161db95511>:24)，其 context 会递归移动整个 KDA module 的所有 projection 参数；offload 场景可能重新引入大权重搬运和 TransData 风险。

也不建议本 commit：

- 把三个 conv module 改成 SGLang 的 merged module；
- 将 upstream FP32 参数直接改成 BF16；
- 改 CANN kernel 接受 `[C,W]`；
- 改 recurrent cache layout。

### 5. 风险与必需测试
