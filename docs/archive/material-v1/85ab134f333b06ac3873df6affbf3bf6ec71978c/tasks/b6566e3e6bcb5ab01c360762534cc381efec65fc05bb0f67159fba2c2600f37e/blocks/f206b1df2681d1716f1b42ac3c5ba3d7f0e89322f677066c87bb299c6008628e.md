4. **[P2] pending run 上的 release/preflight/activate 会先创建 host task**

   [vaws_ready_runtime.py:337](<redacted:local-path:3db0e242f2a0>:337) 对所有 pending action 都会执行 `submit`，不仅是 `poll`。

   我用现有测试 Backend 复现了 `release(pending)`：实际调用顺序是 `status → status → submit → release`，最后因空 fence token 进入 `uncertain`。也就是说，一次本应取消/拒绝的 release 反而分配了 host task 并留下待 reconcile 状态。

   pending 状态应只允许 `poll` 触发提交；其他 action 应无副作用地拒绝或本地终止。

   ::code-comment{title="[P2] Non-poll actions submit pending work before handling the action" body="Calling release, heartbeat, preflight, or activate on an unsubmitted pending run first submits it to the host. A reproduced pending release allocated the task and then became uncertain because no fence token existed. Restrict submission to poll and handle invalid pending-state actions without host mutation." file="<redacted:local-path:3db0e242f2a0>" start=337 end=351 priority=2}

5. **[P2] profiling 参数估算不支持混合 Dense/MoE 层和无 q-lora 的 MLA**

   ::code-comment{title="[P2] Parameter totals ignore MLA Q fallback and mixed dense/MoE schedules" body="When kv_lora_rank is set but q_lora_rank is zero or absent, the Q projection is omitted instead of using the full projection. MoE totals also multiply every component by all layers and ignore first_k_dense_replace and moe_layer_freq. This materially misreports total and active parameters for valid configs." file="<redacted:local-path:44ff386f67b7>" start=157 end=179 priority=2}
