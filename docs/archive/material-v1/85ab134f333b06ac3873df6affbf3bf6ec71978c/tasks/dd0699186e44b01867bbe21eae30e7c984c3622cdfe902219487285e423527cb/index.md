# MindIE Agent：错误可见性与长上下文经验质量

当前任务聚焦 Codex 适配器、knowledge、remote-dev 和 diagnostics 四个组件，重点是禁止用空结果、默认值、静默降级或摘录掩盖必要步骤失败，并在 PR 提交前依据九条设计原则审查；已报告的回归和文档改动仍有未安装、未推送及部分平台验收缺口。历史导入、只保留最新正文、Luna 摘要接线、提交后同步前检索空窗等既有问题仍需与新结论一起跟踪，不能把测试通过泛化为全流程完成。长程任务的核心研究问题已从续接机制转为经验质量与成本控制：脚本可做脱敏、去重和证据关联，但模型若处理大量进度汇报会造成成本不可控，候选筛选又可能漏掉中间的失败、纠正和未验证结论；需要以明确预算、证据边界和遗漏率/质量对照实测，当前没有证明该方案已可上线。

- [错误设计原则、PR 审查与经验质量成本](blocks/781bb7db7ca9d4b267a03d4803aeb338101793b179aee7172ab5938ebca7a3ba.md): Stop 协议保留不触发模型续跑，同时显式报告内部错误；四组件回归据源材料称已通过，但尚未推送或安装。设计原则新增禁止隐藏错误、区分成功/失败/结果不确定、说明失败阶段与不确定副作用，并要求所有开发任务在提交 PR 前逐条 review；测试通过不能替代审查。业界调研指出 checkpoint、compaction、后台记忆整理和增量方案都可能带来重复输入或额外模型调用，当前真正待解决的是从大量进度汇报中筛选有证据的候选经验，以可核算的输入、补读、输出和重试成本生成高质量正文；该方案尚未证明能稳定覆盖埋藏的关键事实。
